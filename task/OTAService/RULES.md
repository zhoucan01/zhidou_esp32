总则
本文件规定 AI 在生成、修改、审查代码时必须遵守的规则。所有输出代码在交付前须逐条自检，不满足者视为不合格输出。

规则 1：单条语句必须保持单行
定义：任何一条完整的语句、表达式、声明、调用链，必须完整书写在同一行内，不得因长度原因人为折行。

具体要求：

禁止手动插入换行符将单条语句拆成多行。

禁止使用续行符（如 Python 的 \、Shell 的 \、C 的 \）来折行。

禁止依赖括号隐式续行来拆行。

禁止因"可读性"主动拆行；可读性通过命名、注释、拆分逻辑单元（拆成多条独立语句或独立函数）解决，而不是拆单条语句。

字符串字面量、正则、SQL 等如超长，同样保持单行，不得用相邻字符串拼接折行。

规则 2：缩进必须真实反映嵌套结构
定义：缩进必须真实、准确地反映代码块的嵌套结构，且在同一文件内保持一致的缩进风格。

具体要求：

缩进单位按语言规范执行：Python / JavaScript / TypeScript / Java / C / C++ / Go 按项目约定，4 空格/级，同一项目内统一；YAML 为 2 空格/级，禁止 Tab。

禁止混用空格与 Tab；同一文件内缩进字符必须统一。

每进入一个代码块（函数体、循环体、条件分支、类体、try/except 等），缩进必须递增一级；退出代码块必须回退到对应层级。

禁止用缩进"制造视觉对齐"而偏离逻辑结构（如把续行参数对齐到左括号位置）；本条与规则 1 冲突时，以规则 1 为准。

空行不携带缩进（不留尾随空格）。

不得出现"缩进正确但逻辑层级错误"的情况，例如把本应属于 if 块的语句缩进到块外。

缩进错误导致语义变化的语言（如 Python），生成后必须逐块核对层级。

规则 3：禁止魔法数字与硬编码字符串
所有常量抽为具名常量/枚举；配置项走配置文件或环境变量。

规则 4：错误处理必须显式
禁止吞异常（空 except/catch）、禁止用异常做流程控制；捕获后必须记录或转换并向上传递。

规则 5：命名规范统一
按语言惯例命名（Python snake_case / PascalCase / UPPER_CASE；JS camelCase 等）；禁止单字母命名（循环计数器 i/j/k 除外）。

规则 6：注释只解释"为什么"
禁止逐行翻译式注释；公共 API 必须有文档注释。

规则 7：输入校验在边界层完成
外部输入（用户、网络、文件）在入口处校验并转换，内部函数信任入参。
