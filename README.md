## 站3自动恢复控制

`PowerRecoveryTask` 每1秒检查一次站3反馈。控制命令成功进入队列后，保存目标档位到
`g_TargetHeater1Gear`（下加热）、`g_TargetHeater2Gear`（上加热）和
`g_TargetPowerMotorGear`（带方向的电机档位）；这些全局变量供读取，设置仍通过控制API。
串口和蓝牙网关的有效FC06/FC10写命令也更新目标。停止命令将对应目标清零，关闭站3总开关
将三个目标全部清零。

- 加热目标档位≥4，且连续两次1秒检查均发现有效有功功率低于200W时，向对应加热通道
  依次发送0档和保存的目标档位。功率取自站3电表总有功功率，单位由mW换算。
- 电机目标档位非0而反馈RPM为0时，向电机通道依次发送0档和保存的带方向档位。
- 只使用最近2秒内收到的站3反馈；总开关关闭、校准进行中或Modbus压测时不触发恢复，
  无效电表读数不参与低功率判断。

恢复指令通过DataCenter队列串行执行，不改变目标档位；同一通道不会重复排队恢复指令。
等待执行或等待0档回显期间若收到停止或换档命令，旧恢复请求取消。异常持续存在时，
后续检测仍可再次尝试恢复。加热目标换档、停热或功率恢复到200W以上（含200W）时，
重新累计低功率次数。已有`Heat2Run`调用保持注释，此任务只恢复实际下发过的非零目标。

## Modbus 支持

本项目支持 Modbus RTU。ESP32-S3 同时作为站号 `1` 的从站和站号 `2`、`3` 的主站网关：

- 站号 `1`：提供 ESP32-S3 本机状态、流程控制以及站号 `2`、`3` 的状态缓存。
- 站号 `2`：执行板，通过 UART2、1000000、8N1 通信。
- 站号 `3`：功率板，通过 UART1、1000000、8N1 通信。
- UART0 和蓝牙均支持 ASCII 网关格式 `MODBUS-TX:[...]`，响应格式为 `MODBUS-RX:[...]`。
- 支持标准 CRC-16/Modbus，CRC 低字节在前；寄存器地址使用 PDU 零基地址。

ESP32-S3 后台按独立周期轮询下游从站：站号2每 20 ms、站号3每 100 ms，并缓存完整状态供上位机读取。完整的功能码、寄存器映射和控制报文见 [Modbus 主站协议](docs/ESP32S3_Modbus主站协议.md)。

### Modbus 设置显示帧率

站号 `1` 的保持寄存器 `0x0010` 用于设置 LVGL 目标刷新帧率，允许值为 `1～20` FPS，上电默认 `10` FPS。使用功能码 `06` 写入后立即生效，读取时使用功能码 `03`；参数越界返回 Modbus 异常码 `03`。

```text
# 设置为最高 20 FPS
MODBUS-TX:[01 06 00 10 00 14 88 00]

# 读取当前设置
MODBUS-TX:[01 03 00 10 00 01 85 CF]
```

成功设置时设备原样回显功能码 `06` 请求。该设置只控制 LVGL 任务的目标调用频率，不保证静态画面产生刷新；实际完成帧数仍应读取输入寄存器 `0x0018～0x0019`。

## 上位机读取 ESP32 全部状态

通过 UART0（115200、8N1）发送以下 ASCII 文本，读取站号 1、功能码 `04`、`0x0000～0x001D` 共 30 个输入寄存器：

```text
MODBUS-TX:[01 04 00 00 00 1E 70 02]
```

应答为 `MODBUS-RX:[01 04 3C ... CRC_L CRC_H]`，包含60字节寄存器数据。ESP32四字节固件版本位于开头的`0x0000～0x0001`，当前固件`0.0.1.8`返回`00 00 01 08`；本机站号和网关协议版本依次位于`0x0002`、`0x0003`。站号2/3的完整缓存仍分别读取`0x0100`、`0x0200`。

| 新增输入寄存器 | 内容 | 单位 |
|---|---|---|
| `0x0000～0x0001` | ESP32固件版本（主、次、修订、构建各1字节） | 四字节版本号 |
| `0x0014～0x0015` | PSRAM 当前可分配的 8 位堆内存余量 | 字节 |
| `0x0016～0x0017` | 内部 RAM 当前可分配的 8 位堆内存余量 | 字节 |
| `0x0018～0x0019` | 最近完整 1 秒窗口内实际完成的画面更新次数 | 帧（窗口固定 1 秒，数值也为 FPS） |
| `0x001A～0x001B` | 同一窗口平均刷新耗时，向下取整 | 微秒 |
| `0x001C～0x001D` | 同一窗口最大刷新耗时 | 微秒 |

诊断字段均为 `uint32`，高寄存器在前、寄存器内高字节在前：`value = (high << 16) | low`。耗时除以 1000 得到毫秒。只读取诊断字段可发送 `MODBUS-TX:[01 04 00 14 00 0A 30 09]`。

内存余量在处理查询时采集，表示空闲堆总量，不是最大连续空闲块或芯片剩余物理容量。显示统计从显示初始化开始划分固定 1 秒窗口，按最后一块 DMA 完成时间归入窗口；一轮局部或全屏更新只算一帧，分块传输不重复计数。刷新耗时使用真实微秒时钟，从 LVGL 开始绘制脏区域到最后一块 DMA 完成，包含绘制、传输、等待和调度时间，不是 CPU 或 PSRAM 利用率。启动未满一个窗口时显示统计为 0；完整窗口无更新时帧数和耗时均为 0。查询不会清零统计，建议上位机每秒读取一次。屏幕静止时 FPS 为 0 属于正常现象。

完整寄存器及流程控制说明见 [Modbus 协议](docs/ESP32S3_Modbus主站协议.md)、[串口上位机控制说明](docs/串口上位机控制说明.md) 和 [蓝牙上位机控制说明](docs/蓝牙上位机控制说明.md)。

ESP32后台按独立周期读取站号2和站号3：站号2的完整状态计划采样周期为20 ms（每秒50次），站号3为100 ms（每秒10次）。上位机透传、业务写命令或从站超时会占用同一命令队列，此时采样按队列顺序顺延。

## 使用说明
代码分为5个部分，分别为 **function**、**hardware**、**components**、**task**、**main**。
**components** 文件夹包含各种片内外设的初始化，**sys** 负责管理各种外设的使用，**sysconfig.h** 包含各种头文件，**sysdepecated.h** 包含已经不使用的**外设**，**sysiicconfig.h** 包含 **iic** 的管理，**syspin.h** 管理**引脚**的使用，**syspwmconfig.h** 管理 **pwm** 的使用。

## LVGL 单屏配置化 UI

`function/UI` 使用一个 LVGL screen 和固定图片/文字槽位承载 29 个逻辑页面，包含首页、Tofu、Plant Milk 和 Clean。

- `ui_init()` 只创建一次 `ui_Screen`；页面切换复用最多 11 个图片槽和 14 个文字槽。
- `Tofu/`、`PlantMilk/`、`Clean/` 分别维护三个功能的页面与交互；`components/myLvgl/` 负责旋钮和业务任务桥接。
- 图片通过 LZ4 压缩后链接到应用，运行时解压到 PSRAM；无需单独烧录图片资源分区。
- `MYLVGL_UI_VALIDATION_MODE` 在 `components/myLvgl/include/myLvgl.h` 中统一控制三个功能。1 为 UI 测试模式；0 使用传感器并启动实际任务。压制通道的临时在位开关独立保留。
- UI 仍调用本分支原有生产任务；压制工艺、豆腐制作、点卤、温度标定和 Modbus 扩展保持本分支实现。
- 旧 SquareLine 导出保留作参考，不加入当前单 screen 界面的编译入口。

## 协议同步规范

当用户说“同步协议”时，必须执行以下流程：

1. 重新读取 `docs` 目录下的全部协议文档，不依赖上一次读取的缓存或记忆。
2. 以对应从站的专用协议文档为寄存器地址、类型、范围和控制语义的最终依据；汇总文档与专用文档冲突时，先按专用文档同步程序，再更新汇总文档。
3. 逐项比对当前程序与协议，至少检查从站地址、串口参数、功能码、寄存器映射、数据类型/字节序、数值范围、控制顺序、轮询解析、容错和示例报文。
4. 根据差异优化程序，并同步更新 `ModbusMap.h`、主站逻辑、对外接口、协议汇总文档和上位机说明；禁止在业务代码中新增裸地址。
5. 完成后执行可用的构建或测试，并说明已修正差异、验证结果与仍需硬件联调的项目。
6. 所有提供给上位机读取的 Modbus 寄存器地址一经发布即冻结。新增字段只能从对应连续寄存器区当前末尾向后追加，禁止插入到已有字段之间、调整已有字段顺序或复用已有地址，以免改变后续字段地址并破坏旧版上位机兼容性。
7. 多寄存器字段必须整体追加并保持连续；已有字段停止使用时保留原地址并标记为“保留”，不得删除后让后续字段前移。追加后同步增加“全部状态”读取数量、协议版本、示例报文和 CRC，并保留旧长度读取兼容性。
