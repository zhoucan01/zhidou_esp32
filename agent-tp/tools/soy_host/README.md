# 豆浆串口上位机

Windows桌面程序，可在连接前选择工艺1（原有流程）、工艺2、工艺3或工艺4。前三种工艺按温度
60/80/85/90/93/95℃依次切换升温阶段，温度回落不会退回阶段。
工艺1温度达到100℃时关闭加热，电机按运行3秒、停止1.5秒的节奏冷却至85℃或以下。
工艺2达到100℃时关闭加热，电机按运行3秒、停止2秒的节奏降温至89℃或以下。
工艺3依据[豆浆加热档位表](./豆浆加热档位表.txt)，独立配置保存在
[auto_heat_process3.json](./auto_heat_process3.json)。七段加热温度、档位及开停时间
按表设置，末段为采集100℃数据延长至100℃：60/80/85/90/93/95/100℃，19/10/10/9/9/7/7档，
常开/常开/6停4/6停15/6停4/5停5/6停4秒。
达到100℃后关闭加热，降至89℃或以下结束；不采用工艺2的720秒强制跳段。
表中未指定电机参数，工艺3沿用当前工艺2配置：1档，前两段开3秒/停2秒，
85～90℃段开4秒/停3秒，其余升温段开3秒/停3秒；降温开3秒/停2秒。
自动加热的下加热档位与电机节奏由上位机通过站3
Modbus FC06 控制，温度回落不会退回阶段。

自动加热各温度段的阈值、加热档位、加热开/停时间和电机档位及运行/停止时间
工艺1配置在 [auto_heat_config.json](./auto_heat_config.json)，工艺2配置在
[auto_heat_process2.json](./auto_heat_process2.json) 中，时间单位为秒。温度段
阈值表示进入下一阶段的温度上限；配置文件随脚本分发，修改后重启程序生效。

## 运行

安装Python（包含Tkinter），在此目录运行：

```powershell
python -m pip install -r requirements.txt
python app.py
```

也可双击 `start.bat`。选择ESP32控制串口和参考温度探头串口，分别设置波特率，
选择工艺后点击连接，收到温度后点击“开始自动加热”。仅采集模式也可选择工艺，
以便在采集文件中标记当前工艺；连接后工艺选择锁定，断开后可重新选择。
控制串口默认115200，温度波特率须
按探头实际设置。串口被IDE串口监视器占用时须先关闭监视器。
成功连接后会记住控制/温度串口号、波特率和是否共用串口；Windows设置保存在
`%APPDATA%/SoyHost/settings.json`，Linux设置保存在 `~/.config/soy_host/settings.json`。

温度格式支持 `T=86.7`、`TEMP:86.7`、`TEMPERATURE=86.7` 和固件 `now:86.7`。
忽略不在0～150℃的值，如-600；支持已有串口软件的时间戳前缀和ANSI颜色码。
当前NB调试任务不持续发送温度，所以通常使用独立参考探头串口。若设备在控制
串口持续输出温度，可勾选“共用串口”。程序不主动请求Modbus温度或修改固件。

启动先发送 `NB+SOYMODE=0,0` 全停并等待设备确认，然后经 ESP32 的
`MODBUS-TX` 网关向站3发送 Modbus FC06：先写保持寄存器 `0x0000=1` 打开总开关，
再写 `0x003C=1` 启动自校准；随后每秒用 FC03 读取 `0x003D` 状态。
只有读取到状态 `2`（完成）才开始发送自动加热档位；状态 `3`（超时）、
校准状态查询异常时继续重试，不启动加热；校准状态读取无有效响应时每3秒重试。
从触发校准起，如果60秒内一直未查询到“校准中”（状态1）则停止；每次有效查询到
状态1，重新开始60秒等待。站3返回状态3时立即停止。自动加热档位写入保持寄存器
`0x0002`，电机档位写入
`0x0004`；写入后必须收到站3 FC06 回显确认，无有效回显时每3秒重发，
连续3次超时后停止自动加热。
工艺1阶段档位为1档=19、2/3档=10、4/5档=9、6/7档=8；3档为每10秒加热6秒，
4档每21秒加热6秒，5～7档每10秒加热6秒。电机保持原节奏：每8秒运行2秒，
电机档位为1。最后有效真实温度全程10秒未更新时，桌面上位机弹窗询问是否结束；等待或选择继续时维持当前阶段的加热、电机开停节奏并继续采集。
每次连续失效只提示一次，恢复有效温度后自动关闭提示并恢复正常阶段判定；再次失效可再次提示。
选择结束时发送全停，但保留连接继续记录；关闭提示窗口等同继续。提示为非阻塞窗口，不暂停串口处理和控制定时器。
温度达到100℃时关闭加热并循环运行冷却电机；有效温度读数降至85℃或以下后
停止电机并关闭站3总开关。
工艺2按 `ToufuMake` 调用的 `SoyMilkMake/HeatSoyMilk` 有效分支设置：
60℃前19档持续加热，60～80℃为10档持续加热，80～85℃为10档开6秒/停4秒，
85～90℃为9档开6秒/停15秒，90～93℃为9档开6秒/停4秒，
93～95℃为7档开5秒/停5秒，95～100℃为7档开6秒/停4秒。
各升温段电机均为1档，前两段开3秒/停2秒，85～90℃段开4秒/停3秒，其余升温段开3秒/停3秒。
工艺2第3～6段超过720秒未到温则进入下一段；最后一段不因720秒超时提前降温，持续至100℃。
固件的98℃确认函数与95/93℃撒水动作不在本上位机控制范围内：工艺2以参考温度
首次达到100℃作为降温入口，不自动控制清水泵。阶段时间基于上位机单调时钟，
Modbus回显/串口调度可能使实际开停边沿稍有延迟。
断开或关闭前也尝试全停并等待确认。
物理串口断线时软件无法保证停机，设备必须具备自身保护。不要同时运行
`HeatSoyMilk` 固件自动流程，避免两个控制源争用执行器。
上位机温度显示下方的“当前下加热档位”根据站3 Modbus FC06 回显确认更新；
周期关断时显示0档。

页面另提供开阀、关阀、蠕动泵正转、反转和停止按钮，对应命令为
`NB+VALVE=OPEN`、`NB+VALVE=CLOSE`、`NB+HOSEPUMP=FORWARD`、
`NB+HOSEPUMP=REVERSE` 和 `NB+HOSEPUMP=STOP`。泵正反转固定为90%速度；
控制器返回对应的 `... OK` 行表示命令已接受并进入执行队列，不代表机械动作已完成。
这些是独立手动执行器控制，不会由“停止全部加热和电机”按钮自动关闭阀门或停止蠕动泵；
使用后请按需要明确发送关阀/泵停止指令。

本程序未连接实机测试，不会自动打开串口或启动设备。

## 自动记录

### 仅采集模式

连接前勾选“仅采集”并选择工艺。连接后锁定这两个选项，需要断开后才能切换。
此模式禁用自动加热和停止按钮，断开、关闭、温度超时、串口异常均不发送
`NB+SOYMODE`。仍每秒发送只读Modbus请求以获取NTC ADC，真实温度、NTC、
本地拟合和日志记录保持工作；另每100 ms请求一次站3运行快照。可用于固件自行
运行时旁路采集，不负责设备停机。
未勾选时保持原自动控制行为，断开和关闭前仍发送全停。

连接后每秒通过现有 `MODBUS-TX` 协议读取站2输入寄存器0～68，提取NTC1/2/3
完整uint32 ADC并显示。无需更新固件。每次连接自动创建 `agent-tp/data/captures/YYYY-MM-DD/时间戳.csv`
和 `agent-tp/data/captures/YYYY-MM-DD/时间戳-serial.txt`，分别保存采样和完整收发日志，每条记录立即刷新。
日志目录已加入Git忽略规则。

上位机另每100 ms经 `MODBUS-TX` 向站3发送 FC04 `0x0000` 起始、24寄存器的只读快照
请求（`03 04 00 00 00 18 F1 E2`），将首个输入寄存器 `0x0000` 的实际转速 RPM
及接收时间写入 CSV。仅在收到有效 CRC 的完整快照后记录；快照超过500 ms未更新时，
后续 CSV 行的转速留空。轮询采用单个未完成请求等待应答，避免无响应时堆积请求。

上位机每秒通过 `MODBUS-TX` 读取站号1 FC04 输入寄存器 `0x000C～0x000D`
（`01 04 00 0C 00 02 B1 C8`），按ABCD字序解析ESP32板级float32温度。页面真实温度
旁显示ESP32板级温度及带符号温差（板级温度减真实温度）；
真实温度超过有效期限（全程10秒）、板级温度超过3秒未更新时，对应数值或温差显示为 `--`。
串口日志记录板级温度和温差，CSV也保存板级温度、
接收时间及误差列；温差仅在真实温度和板级温度都有效时写入。

CSV记录工艺、真实温度、ESP32板级温度、三路原始ADC、各数据的接收时间、模式，以及NTC1/2
本地查表温度。NTC3没有标定，保留ADC。真实温度超过有效期限、ADC超过3秒未更新
时对应采样列留空，避免把旧值当作当前数据。两路串口异步接收，行内是最新
快照，不代表传感器严格同一时刻采样，应按各自接收时间分析。

控制串口收到固件 `ntcTemp: NTC temperatures: NTC1=... C, NTC2=... C,
NTC3=... C` 日志时，界面会在三路ADC下方显示三路固件查表温度及相对真实温度的
带符号误差（NTC温度减真实温度）。真实温度超过有效期限或NTC温度日志超过3秒未更新时，
误差显示为 `--`。CSV另记录三路固件查表温度、接收时间及误差列。

本地NTC2拟合使用连接时工程 `ntcTemp.h` 的MACHINE默认定义，不自动识别设备
实际烧录配置；若设备使用不同配置，拟合列不能视为设备直接上报温度。

电机状态区显示最近写入已确认档位、实测RPM及待确认档位；RPM过期显示未知。最近10条指令列表显示毫秒发送时间及串口写入结果（仅操作指令），设备确认见日志。电机控制日志会注明正转/反转/停止和具体档位，重发同样记录。

真实温度采集倒计时显示剩余秒数、当前超时限时、最后有效温度和采样年龄；有效温度收到后重新计时，`T=-600.0` 等无效数据不刷新倒计时。温度超时日志包含最后有效值、采样年龄和当前限时。

### 温差统计

实时监测页在指标卡片下方显示本次连接的最大绝对温差、≤1℃覆盖率、≤2℃覆盖率、≤3℃覆盖率和有效样本数。温差为板级温度减真实温度，最大值和覆盖率按其绝对值计算，阈值包含恰好1℃、2℃和3℃。随趋势每秒至多采样一次，仅两路温度均新鲜且温差为有限数值时计数；过期、缺失、NaN/Inf不进入分母。覆盖率为有效样本占比，不是按串口消息数量或精确持续时间加权。

统计累计整个连接周期，不受趋势图最近1800点窗口截断影响；重新连接清零，无有效样本时显示 `--`。统计是历史累计值，当前温度过期时已有统计仍保留。

校准阶段（停止准备、使能、触发及运行）全部排除：期间的样本不计入最大温差、覆盖率的分子和分母及有效样本数。校准结束后恢复累计，校准前的有效统计保留；校准期间曲线和原始记录仍正常显示、保存。

最大绝对温差仅统计真实温度≥80℃的有效样本（包含恰好80℃，降温低于80℃后也不计入）；
尚无符合条件的样本时显示 `--`。≤1℃/≤2℃/≤3℃覆盖率、≤3℃覆盖率和有效样本数仍按原有全温区口径统计。

所有工艺均使用有效真实温度作为100℃终点：98～100℃继续运行最后一档，达到100℃后关闭加热并进入各自降温流程；采集继续。温度超时按上述询问策略处理，通信故障停机保护仍生效。

统计区另显示最近一次绝对温差严格大于2℃时的本地采样时间、真实温度、板级温度和带符号温差。
超差记录按全温区有效采样更新，恰好±2℃不更新，恢复正常后保留最近一次记录；重新连接时清空。
该记录不受最大温差的80℃门槛限制，校准、过期和缺失数据均不更新。原始CSV继续保存完整采集数据。

工艺4为[植物奶流程](./flow/植物奶完整流程.txt)的加热采集版，配置在
[auto_heat_process4.json](./auto_heat_process4.json)：60℃前及60～95℃均为14档持续加热，
95～100℃使用8档持续加热；取消60℃和95℃恒温等待，不自动加水、9档破壁、开阀或排浆。
搅拌电机为1档，开3秒/停0.5秒。达到真实温度100℃关闭加热，仍按该搅拌节奏降至85℃或以下全停。
工艺4没有阶段超时跳转，真实温度失效时询问是否结束，站3通信失败仍触发停止保护；0.5秒边沿可能受串口回显延迟影响。

真实温度失效期间不按旧值切换阶段，也无法判定真实100℃终点；板级温度不会自动替代真实温度。底层Controller未配置超时交互回调时仍按原有自动停止策略运行。
