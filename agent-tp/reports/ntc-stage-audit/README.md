# 60℃以上温度段与功率工况排查

输入：[原始CSV](../../data/captures/2026-11-04/20261104-115358-138914.csv)。复现脚本：[audit.py](../../tools/ntc-stage-audit/audit.py)。逐样本选表结果：[selection.csv](selection.csv)。

## 方法

提取事件来源为NTC、真实温度≥60℃的行，避免其他串口事件重复快照。六个升温段共1569行全部进入选表检查，包括580行参考温度接收时间超过2秒的快照；这些行仅用于转换可用性检查，不用于精度结论。另48行模式0属于启动/降温/停机，未强行按升温工况映射。未插值，也未删除ADC异常点改善结果。

脚本编译并调用当前生产C代码，功率档位依据本次工艺2模式对应配置推断，不把加热周期中的瞬时0档误当作新温区。两种诊断场景分别用参考温度、板级温度作为默认模板推断的上次温度，三路独立查询。输出channel=0/1/2代表NTC1/2/3，scenario=0/1代表上述两种场景。原始CSV未记录各通道真实内部历史，故这不是完整状态回放。关闭电机门控仅检查选表可用性，不证明实际滤波接受率或测温准确度。

## 本轮新增问题与修复

NTC1 7档5/5秒曲线只有两个ADC节点。遍历第二节点时，旧代码把倒数第二点设为尚为空的last，导致已有两点也无法进入5℃外推分支。原先筛选参考接收年龄≤2秒的92个93～95℃样本中，12个返回NaN；本次修复为第二节点的前一个点是first。完整1569个升温样本在三路、两种诊断场景下均返回有限值。保留5℃外推及ADC异常保护，并补充两节点工况的主机回归测试。

## 仍有的覆盖不足

“有对应组”不代表“对应组覆盖本次ADC”。当前代码优先选择覆盖ADC的最近曲线，可能借用不同档位或同档不同加热节奏。

- 60～80℃：NTC1全部使用10档常开；NTC2有139/268、NTC3有178/268次借用19档常开，因为该两路10档标定ADC区间与本次采样偏离。
- 80～85℃：NTC1有16/135次借用10档常开；NTC2全部135次使用10档常开，NTC3亦大量使用常开。不是没有6/4组，而是其ADC区间不足。
- 85～90℃：NTC1有32次借用10档6/4及1次借用9档6/4，其余主要为9档6/15；NTC2/3回退更频繁。
- 90～93℃：NTC1有17/139次选择9档6/15，其余为9档6/4。
- 93～95℃：NTC1 80次选择7档5/5，10次7档6/4，38次8档6/4，10次9档6/4；24次无曲线直接覆盖，依靠受限外推。
- 95～98℃：NTC1 157次7档6/4、11次7档5/5、29次8档6/4；三路均可覆盖ADC，但跨档替代仍需要独立精度验证。

上述具体计数为scenario=0；scenario=1结果基本一致，详见CSV。默认10/9档模板与原标定表使用电机2秒开/6秒停，本次上位机配置却使用3/2、3/3或4/3秒。7档模板已匹配3/3秒。这是工况/标定节奏不一致，不是功率档位漏配；直接把旧表改名成新节奏不等于重新标定，因此本轮没有改写实测表或伪造匹配组。

模式0的降温部分：专用电机3/2秒降温数据库仍为空，代码回退旧降温组。不能宣称该48条已有相同节奏的独立标定。完整CSV中三路查表温度列为空，板级读数只能代表主温度，不能用于证明三路拟合精度。

## 验证与结论

运行 `PYTHONDONTWRITEBYTECODE=1 /usr/bin/python3 agent-tp/tools/ntc-stage-audit/audit.py` 可重新生成选表明细（编译临时产物在build）。主机选表审计、既有test_ntc_reaccept与test_ntc_gear_fallback均通过。未实机烧录，未完整回放电机/滤波状态，未用同批拟合宣称独立验证。

现阶段应将“不会因缺档/两节点外推失败而算不出”与“各通道准确”分开验收。进一步提升NTC2/3及跨档区间精度，需要按实际电机节奏和加热节奏分组标定，并用另一批数据验证；本轮保留现有测量数据库。
