# 124212批次：第6000行后偏差与温度数据库重标定

输入：[原始CSV](../../data/captures/2026-11-04/20261104-124212-441968.csv)及同目录串口日志。第6000行约为13:01:29，参考91.7℃，模式5（9档开6停4秒）。本报告按CSV行号理解“6000往后”。

## 原因与证据

第6000行后，以板级温度事件为单位，要求最近参考温度接收年龄≤2秒，避免其他事件重复快照：

|模式|有效比较次数|平均绝对误差℃|最大绝对误差℃|
|---|---:|---:|---:|
|5：90～93℃|32|0.356|0.649|
|6：93～95℃|71|0.463|0.718|
|7：95～98℃|99|2.238|3.755|
|0：后续停机/降温|42|3.741|4.055|

高温ADC仍变化，主温度停在约94.145℃，属于保持旧温度的特征，不能解释为ADC不变。上一轮已确认的7档缺默认模板、窄曲线被选中、两节点无法外推问题，以及电机采样门控和趋势拒绝，都可能导致维持旧值。日志没有固件版本与逐次内部拒绝原因，不能证明哪一个分支单独造成了本次冻结；换表需要与前几轮选表/滤波修复共同部署。

此外，10/9档旧标定组为电机开2秒/停6秒，而本次工艺3分别使用3/2、3/3、4/3秒；NTC2/NTC3旧曲线ADC覆盖也与本次数据明显不符。这是实际标定工况变化，不能只改档位名称消除偏差。三路查表温度列为空，不能将板级温度误差当成三路误差。

本次最高参考温度98.2℃，升温标定样本只到约97.89℃。模式0不是100℃采集成功的证据，不能补造98～100℃节点或声称100℃精度已验证。

## 标定与修改

执行脚本：[calibrate.py](../../tools/ntc-recalibrate/calibrate.py)。更新实际固件使用的`function/ntcTemp/tables/NTC3/ntcTemp_machine3_operating_table.inc`，并使默认10/9档工况模板对应本次电机节奏。未修改旧的一维表，它们不是MACHINE=3当前多工况查询的数据库。

- 1218次60℃以上升温NTC事件，仅保留RPM反馈为0、连续停机≥500ms、最近RPM反馈年龄≤1秒的数据。854次因电机未稳定/反馈不新鲜排除，364次接受，每路独立标定。
- 参考温度按接收时间线性插值，仅允许前后参考间隔≤6秒，无区间外插值；本次电机筛选后无需再剔除参考缺失样本。ADC事件按NTC接收时间去重。采样记录见[calibration_samples.csv](calibration_samples.csv)。
- 按模式2～7的功率、加热节奏、电机节奏、1150mL和通道生成18组曲线。水量依据当前1150mL项目默认值，CSV本身不提供独立水量证据。模式来自上位机工艺，不等同于每次瞬时加热开关反馈。
- 16 ADC一箱，取中位数，再做加权保序回归，使ADC上升时温度不增加。仅做稳健汇总，不按温差大小删异常点。最终表用所有接受样本重建。
- 10/9档增加本次电机节奏的新组，旧节奏组保留；7档相同工况的旧组用本次较密的测量曲线替换。其他水量、低温、8档、降温和其他机器数据库保留。变更前完整表见[operating_table_before.inc](operating_table_before.inc)。
- 原有ADC异常、电机门控、温度趋势以及5℃外推限制均保留。数据库优化本身不会绕过滤波拒绝或恢复计时。
