# 98℃ 有效采样窗口确认

将 DataCenter 的 98℃ 判定改为按“有效采样次数”计：每拿到一次新鲜、有效的主温度更新才记一格（同一次搅拌停机窗口内间隔 <1 s 的重复读取只算一次）；最近 5 次有效采样中至少 3 次 >=98℃ 即确认。温度低于 97℃ 时清空重新计，保证每次升温都从干净状态开始。

不按墙钟时间判断的原因：主温度只在搅拌电机停转、稳定 200 ms 后才更新，98 段搅拌开3停1，等于约每 4 秒才有一格新值；“5 秒窗口内 3 次”会把采样间隔本身算成不合格，实测首次读到 98℃ 后要 48 秒才判定成立。
使用现有过滤后的 g_DataPool.temperature，未修改 ADC、查表、主温度滤波或寄存器。只保留最近三次命中时间即可判断；恰好距当前五秒的命中移出窗口。读取确认状态时实时检查过期，断流不会一直通过；恢复采样不补算缺失秒数。保留现有温度更新门控（包括停机采样策略）。采用独立临界区保护跨任务读写。

回归测试：agent-tp/tests/firmware/test_temperature_over98_window.c，从生产代码提取宏和函数到 build/temperature_over98.inc 后使用 GCC 编译。覆盖首次无样本、同一停机窗口内重复读取只计一次、三格达标即确认、采样间隔任意、低于 97℃ 清空、最近五格滚动淘汰旧命中、非有限温度不计入采样。
