# ADC双向去噪与持续变化接纳验证

日期：2026-10-28。修改对象：默认`MACHINE=3`的NTC滤波；其他机型的查表分支不改变。本次未改标定表、档位、电机节拍或协议寄存器。

## 1. 数据说明与结论

按用户指定的`agent-tp/data/testdata/ntcdata/`读取7份CSV，只取`事件来源=NTC`的本次原始ADC及接收时间，按时间戳去重，不把其他事件里的重复快照当新样本。

共22,295条三路ADC快照，即66,885个通道值。相邻快照之间三个通道分别计数，发现437次绝对变化>200 ADC，其中201次上跳、236次下跳；416次发生在相邻记录间隔≤1.5秒时。同一时刻多个通道可能同时计入，不能理解为437次独立故障。

这些变化是需要诊断的候选，不全部等于电气噪声：大采样间隔、工况切换或真实热变化也可能产生大差值。各文件记录间隔中位数约1.01～1.04秒，不能还原固件20毫秒采样下的脉冲波形。

| 文件 | 三路快照数 | NTC1/2/3的>200变化次数 | 其中≤1.5秒次数合计 | 最大绝对变化ADC |
|---|---:|---|---:|---:|
| 200V-20261027-142003-970824.csv | 4,054 | 8 / 6 / 8 | 22 | 332 |
| 20261027-184942-917636.csv | 5,086 | 32 / 25 / 25 | 82 | 1,025 |
| 210V-20261027-114351-278445.csv | 3,176 | 3 / 3 / 6 | 8 | 1,380 |
| 220V-20261027-110503-922903.csv | 2,044 | 56 / 51 / 64 | 158 | 739 |
| 230V -20261027-010802-159323.csv | 1,881 | 2 / 9 / 2 | 13 | 236 |

| 20261027-232523-940824.csv | 3,298 | 0 / 0 / 0 | 0 | 无>200变化 |

因此不能只保护ADC上跳，也不能认为“收集足够多异常点”就意味着真实状态改变。本次采用**双向隔离＋连续一致确认＋拒绝值不训练历史＋真实时间接纳**。

## 2. 实际修改

### 2.1 ADC可信窗口与候选窗口完全分离

新点与可信20点中值的差值，无论正负，绝对值>200时不进入可信窗口，也不把替代旧中值反复填进窗口。

独立候选必须同时满足：

- 至少8个连续有效点，整个候选过程跨度至少140毫秒；点多但时间不够也不接纳。
- 相邻候选点间隔≤100毫秒，方向一致，整段原始ADC极差≤40。
- 出现正常点、0或4095及以上无效值、方向改变、候选离散或时间不递增时，打断原候选。
- 电机边界、工况组变化清理未确认候选，不能跨不相关过程拼接。

满足后，用候选中值重建ADC窗口；不是把每次短异常的一两个点慢慢混入正常窗口。温度层还会独立检查新ADC换算出的温度，所以ADC新状态确认不等于温度直接无条件放行。

8点、140毫秒、100毫秒间隔和40 ADC极差是保守的初始工程参数。以20毫秒轮询计算，8点跨度为140毫秒，可在0.5秒停机扣除200毫秒等待后的窗口内完成。真实队列延迟或信号波动可能延长确认；这组参数没有被当前约1Hz CSV证明为最优值。

同时修正DataCenter的重复等待：已有停机指令且从该指令起的200毫秒等待已结束时，RPM延迟回零不会再从回零时刻额外等待200毫秒；没有停机指令时，仍从首次观测零RPM起等待200毫秒。这保留原先指令门控的等待标准，避免0.5秒停机窗口被分成两段不足8点的短片段。集成测试验证了这种情况下ADC从2300持续变为2700可以完成确认；温度层仍独立判断其换算变化。

### 2.2 温度接纳使用真实时间

趋势拟合改用`esp_timer`微秒时间戳，保留最多100个真实接纳点。正常值按MAD阈值判断；异常新状态至少8点、140毫秒、间隔≤100毫秒，候选温度极差≤0.2℃。

重新接纳时，还要求整个候选范围相对最后真实接纳温度满足：

```text
允许变化量 = 0.5℃ + 1℃/秒 × 距离最后真实接纳点的实际时间
```

因此停采3秒后真实变化2℃，不会再按20毫秒对应0.02℃直接否决。相反，刚刚建立正常点后的短异常簇，也不能只因数量达到8个就立即变成新温度。

趋势预测只用来判别，拒绝点输出最后真实接纳值；预测值和替代值不再写回趋势历史，也不刷新其真实接纳时间。避免“模型预测自己、历史越来越像旧预测”的反馈问题。

### 2.3 重置后不能绕过检查

电机重新运行、工况组变化时，清除候选并把温度趋势历史收缩到最后真实温度及时间锚点；不会清空成无基线状态后把接下来的前三点直接放行。ADC可信中值保留，升降温阶段切换仍按原行为完整清窗。

## 3. 实测幅值注入比较

调用改动前后的真实`update_adc_window()`，将416次短间隔变化的带符号实测幅值分别注入合成序列：可信ADC固定为2000，先建立20点历史，再循环5轮“7个带偏差点＋1个正常点”，频率50Hz。

这是假定真值已知的**合成压力测试**。幅值来自日志，排列和时间为测试构造，不是恢复真实采样波形，不计算真实温度精度。

| 指标 | 旧实现 | 新实现 |
|---|---:|---:|
| 注入组数 | 416 | 416 |
| ADC输出曾偏离固定真值超过200的组数 | 231 | 0 |

旧实现限制上跳但放行下跳；反复下跳会占据中值窗口。新实现中，7个异常后出现正常点就会清候选，因此不能跨周期凑够8个。

**0组不是“实机100%去噪成功率”。** 连续8个以上、足够集中且持续的错误平台仍可能被认为是新状态；没有独立参考时，持续故障与真实变化可能无法仅凭本通道区分。

## 4. 行为回归验证

[新增测试](../../tests/firmware/test_ntc_reaccept.py)直接编译运行生产代码，验证：

- 10,000次交替大幅ADC噪声不改变可信窗口。
- 1,000轮“7异常＋1正常”不会拼接计数，也不会污染正常历史。
- 采样缺口、重复时间戳、无效值、电机边界能打断候选。
- 连续稳定ADC上升和下降均可重新接纳，超高速重复点不能绕过140毫秒条件。
- 温度上下交替异常不训练模型；真实2℃变化在3秒采样间隔后可确认接纳。
- 0.2℃/秒正常渐变可跟随；完整三路换算中，被ADC层拒绝的点不会继续训练温度趋势。
- 延迟RPM回零不会产生重复的200毫秒等待，连续确认可在0.5秒停机窗口内完成。

已有短停机测温、站3恢复控制、显示诊断和编码器测试通过；三个主通道的工况数据库回归通过，`MACHINE=1/2/3/4/6`分支编译检查通过。完整ESP-IDF构建通过，未烧录设备。

[趋势探针结果](2026-10-28_ADC去噪验证/趋势接纳对照.csv)还保留了不能回避的对照：相同87℃输入若被定义为“85℃真值＋2℃持续故障”，新逻辑也会在确认后接纳；若定义为真实87℃，则解决了旧逻辑锁在85℃的问题。两者说明重新接纳与故障识别存在边界，而不是已解决所有错误数据。

## 6. 仍需上板确认

原始记录间隔约1秒，无法验证140毫秒候选的实机分布；下一轮应记录原生停机窗口内的ADC、接纳/拒绝状态及时间戳，检查强干扰是否恰好形成稳定假平台，同时测量补水、搅拌后的真实响应延迟。

本次没有新增最大保持时长后的自动停机策略，也没有消除不同工况表之间的固有温差。新参数需要实机确认，不能将本次压力测试结果当成温度标定精度提升值。
