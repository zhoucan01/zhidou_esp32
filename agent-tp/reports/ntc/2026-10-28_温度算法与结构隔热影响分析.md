# 当前温度准确度的算法来源与结构隔热影响

日期：2026-10-28。依据：当前工作区代码、现有标定表、历史分析记录、用户提供的隔热改造前后反馈及传感器厂商资料。

## 1. 结论

**结构已经加强隔热。用户补充：改造前的升温表所需补偿比现在高约10℃，当前升温、降温温度均较准确。** 这是本机改造前后的实机使用反馈，原报告将隔热视为尚未实施的建议，现据此修正。

据此，当前准确度应归因于**结构改善与算法标定共同作用**：隔热改造已经显著降低了升温测温关系所需的补偿，实测工况标定及升降温分表处理剩余偏差，停机采样和滤波减少干扰与跳变。不能将当前准确度全部归功于滤波，也不能因旧表补偿后同样准确，就认为结构改进没有收益。

“约10℃”目前应记录为**用户反馈的升温补偿差值**，不能直接写成最终测温误差降低10℃、全温区统一偏移10℃、隔热效率提高某个百分比，或降温补偿也减少10℃。尚未提供改造前后原始数据、对应温区、同条件比较及补偿的正负定义，因此不推断探头原来偏高还是偏低，也不把差值全部定量归因于某一条热路径。

这一反馈支持：结构热耦合是此前升温补偿需求的重要影响因素，改善幅度值得重视，不能仅视作小幅降噪。减少加热器到探头的旁路传热、保留探头到液体的良好导热，是与该现象一致的机制解释；具体占比仍需原始数据确认。当前各算法也没有做过逐项关闭的对照，不能分配贡献百分比。

### 1.1 如何理解“以前补偿比现在高10℃”

| 项目 | 当前可下的结论 |
|---|---|
| 结构状态 | 已加强隔热，不是待实施方案 |
| 改造前后升温补偿 | 按用户反馈，旧补偿比新补偿高约10℃；这是补偿量的差异 |
| 当前升降温准确度 | 用户反馈较准确，本报告未重新实测 |
| 结构收益 | 升温补偿需求已明显降低；影响不应被忽略 |
| 尚不能量化 | 原始测温误差改善值、热耦合下降比例、跨温区一致性及结构与其他变化的各自占比 |

即使前后最终显示都准确，较少依赖大补偿也有工程价值：意味着当前结构下需要修正的测温关系发生了明显变化。跨功率、跨水量或跨样机是否更稳定，仍需独立验证。新结构应使用对应的新标定，不能给所有旧表节点统一加减10℃代替重新标定。

## 2. 当前实际使用的温度路径

分析以源码默认 `MACHINE=3`、`NTC_TEMP_MACHINE3_PRIMARY_CHANNEL=1` 为准；构建时若覆盖宏，需重新确认。

```text
站2原始 NTC1/NTC2/NTC3 ADC
  → DataCenter停机采样门控
  → 每通道高ADC尖峰限制 + 20点ADC中值
  → 升温/降温阶段选择 + 工况数据库查询、线性插值
  → 每通道温度趋势/残差滤波
  → 选择NTC1作为主温度
  → DataCenter的20点温度排序滤波
  → g_DataPool.temperature / getTemp() / 制作流程判断
```

三路温度分别计算并输出日志，**当前主温度不是三路平均或三路融合**。`MACHINE=3` 实际使用的是 `ntcTemp_machine3_operating_table.inc` 工况数据库，旧的六张独立升降温表不参与该模式的运行时换算。

部分旧README段落仍描述“数据库未匹配时回退旧表”“ADC下降触发降温”等历史行为；本报告按当前C代码分析。

## 3. 哪些算法影响准确度

| 环节 | 当前实现 | 主要影响 | 能力边界 |
|---|---|---|---|
| 实测标定 | ADC与参考温度配对；按32 ADC分箱，温度取中位数，再做加权单调递减PAVA拟合 | 校正NTC非线性及本机安装、传热关系；是绝对准确度的主要基础 | 也可能吸收特定实验的动态滞后和偏差，不能自动迁移到另一种结构 |
| 工况分组 | 按通道、升降温、加热档位、加热开停时间、电机档位及开停时间选择组 | 同一ADC可在不同工况下换算成不同温度，减少将所有工况硬套一条曲线的偏差 | 是经验补偿；运行时并未根据实际W值建立连续热传导模型 |
| 相邻节点线性插值 | 在所选组的ADC节点间插值 | 保留实测关系，又避免只取最近节点造成台阶 | 表外数据不等于经过验证的数据；边界允许最多5℃的端点外插 |
| 升降温阶段管理 | 周期停热保留升温状态；关热、主温度≥98℃且20点ADC后半均值高于前半时锁存降温；再加热解除 | 减少错用阶段曲线引入的系统偏差 | 阶段识别有条件和延迟，并不代表任意温度停热都立即进入降温表 |
| 电机停机门控 | 常规路径要求RPM为0并稳定200 ms；停止命令满200 ms另有5个采样的临时放行窗口 | 避开部分电机运行干扰，改善输入数据质量 | 临时放行可能发生在RPM反馈仍非0时，不应声称每个点都已证实物理停转 |
| 高ADC尖峰限制 | 新点高于自身窗口中值超过200 ADC时，用旧中值替代 | 抑制孤立高ADC尖峰 | 单侧处理；不是所有异常都能识别，真实大幅降温也可能受限制 |
| 20点ADC中值 | 三个通道独立维护；电机重启保留ADC历史，重置温度趋势 | 降低偶发ADC噪声；短停机窗口可跨周期积累，不再反复清空 | 会增加响应延迟；20点是有效采样点，不一定代表连续0.4秒 |
| 鲁棒趋势滤波 | 最多100个点；抽取最多10点做Theil-Sen斜率估计；以MAD形成0.5～2℃的残差阈值 | 压制与近期趋势不一致的温度跳变 | 不能纠正持续存在的错误标定；也可能延缓真实温度突变 |
| DataCenter输出滤波 | 最多20点温度按高到低排序；样本不足7点取中间值，否则取第4～7高的4个值平均 | 平滑输出并偏向较高温度侧，抑制低温异常 | 不是无偏平均：升温可能减轻滞后，降温可能增加偏高和滞后 |
| 98℃映射与确认 | [97.9,98.0)℃映射为98℃；达到98℃连续确认5秒后结束相应加热阶段 | 稳定工艺阈值，避免一次跳点触发流程 | 属于流程稳定性处理，不能作为测量精度提高的证据 |

趋势滤波以每个有效采样点20 ms估算变化速度，预测斜率限制相当于1℃/秒；这是预测与异常判断的尺度，不是将每个正常输出都硬性限制为1℃/秒。电机间歇运行时，点数窗口不能直接解释为真实墙钟时长。当前在电机重新运行时重置趋势，能减少长采样间隔被当成连续20 ms的影响。

数据库没有匹配组或超出允许范围时，会保持最近有效温度。因此“显示平滑”“长时间不变”均不能单独证明准确；必须同时看原始ADC、有效更新、所选工况和参考温度。

### 3.1 标定数据筛选也有重要影响

`calibrate_machine3_database.py` 将参考温度按采样时间插值配对，参考点间隔超过2秒不使用；按电机零档确认后至少500 ms筛选数据，再分工况拟合。分箱和PAVA降低噪声引起的局部反向曲线，但不会自动识别参考探头位置错误或整段时间偏移。

当前运行时的200 ms放行条件与建表时的500 ms筛选条件不同。尤其“转3秒、停0.5秒”的窗口，使用的是比建表筛选更早的停机片段，需要在实际节拍下验证，而不能只引用停机较久时的标定误差。

### 3.2 工况匹配与实机流程仍有差异

无参数温度接口根据当前有效加热档位和最近温度阈值选择预置工况，不会测量实际的加热、电机占空比。当前升温数据库预置电机节奏主要是转2秒、停6秒，降温工况是转3秒、停1.5秒；`HeatSoyMilk()` 多数温段及降温段实际使用转3秒、停0.5秒。另外，高温升温预置组为8档，而当前流程存在7档调用。

这些差异不推翻现机“很准”的反馈，但说明**当前准确度不能仅靠配置名推断，也不能保证换档或换节拍后仍同样准确**。结构优化后应按实际档位和节拍重新验证。此次仅分析，不修改流程、温度算法或标定表。

## 4. 项目中可量化的依据

### 4.1 当前数据库中，相同ADC的阶段差异

对当前运行时数据库逐行解析得到21个“通道×工况”组、283个节点。取NTC1各升温组与降温组**共同ADC区间的中点**，分别线性插值，不做表外外插：

| 升温组：档位、开/停秒数 | 比较ADC（显示值取整至0.1） | 升温表温度 | 降温表温度 | 升温表－降温表 |
|---|---:|---:|---:|---:|
| 8档，6/4秒 | 1683.1 | 96.482℃ | 96.937℃ | −0.454℃ |
| 9档，6/4秒 | 1847.3 | 91.140℃ | 91.705℃ | −0.564℃ |
| 9档，6/15秒 | 1963.9 | 87.657℃ | 87.972℃ | −0.315℃ |
| 10档，持续加热（配置1/0秒） | 2370.8 | 74.257℃ | 79.370℃ | −5.112℃ |
| 10档，6/4秒 | 2111.1 | 82.550℃ | 84.863℃ | −2.313℃ |

实际计算采用未舍入的区间中点。19档升温组与当前降温组无共同ADC区间，未比较。

这些数值是**已标定曲线之间的差异**，不是本次实测误差，不是相同液温下切换功率的试验，也不是各工况最大差异。不同组来自不同温区、时刻和热历史，混合了探头局部受热、热惯性、液体混合状态、采样节拍及电测变化等因素。

它们支持“分工况/分阶段标定对部分温区很重要”，但不支持“加热传导造成5.112℃误差”或“隔热可以改善5.112℃”这样的因果结论。

### 4.2 历史报告支持什么

[2026-10-14机器1 NTC2二维标定报告](2026-10-14_NTC2二维标定及原算法对比报告.md)中，同一批87个留出点上，一维表MAE为2.003℃，ADC×档位二维表MAE为0.618℃，约下降69.1%。这说明考虑工况可能显著改善该批数据的换算误差，**不能将69.1%解释为当前机器3的改善幅度或隔热收益**。

[NTC模块README](../../function/ntcTemp/README.md)记录了多次重标定和较小的同批留出误差，其中也包含已经不参与当前换算的旧相位表。每5点留1点仍是同次采集、相邻样本高度相关的验证，不能作为当前整机跨批次精度或算法贡献率。

本报告没有重新采集温度，也没有据此宣称整机达到±0.1℃等精度等级。

## 5. 结构隔热影响的是哪一部分

应区分三条热路径：

| 热路径 | 结构方向 | 对测温的预期影响 |
|---|---|---|
| 液体/目标测量面 → 探头 | 保持良好、重复一致的热接触，减少不必要的接触热阻和热容量 | 更接近目标温度，降低响应滞后 |
| 加热盘/高温底座/热支架 → 探头 | 降低绕过液体的旁路导热、热辐射及热空气影响 | 减少局部热源对探头的额外加热及余热影响 |
| 液体/桶体 → 外部环境 | 桶体保温会改变整机散热边界 | 可能减少热损失、改变升温和降温速度；不是直接等同于测温更准 |

探头实际测量自身温度，目标液体到探头的热接触和其他热源到探头的耦合共同决定偏差。TE建议隔离不希望测量的热源，并指出响应时间由热容量及传热条件决定。此原则支持优化传热路径，但没有给出适用于本机的固定改善比例。[TE：测量集成与时间常数](https://www.te.com/en/products/sensors/temperature-sensors/resources/digital-over-analog.html)

如果隔热只加在桶体外侧，可能使同档位下液体升温更快、自然降温更慢，甚至改变加热盘局部温度。不能据此直接认定探头的旁路热耦合减小。需要结合探头安装、金属连接和加热器位置判断；本仓库未提供足以计算这些热阻的结构尺寸、材料和安装图。

电机或加热开关导致的瞬时ADC跳变还可能来自供电、参考电压、地线或电磁干扰，机械隔热对此没有直接修复作用。NTC激励电流产生的自热也与加热盘向探头传热不同；ADI的热敏电阻设计资料说明了激励、自热、ADC和比率测量对精度的影响，不能将本机所有功率相关误差都归为热传导。[ADI：NTC测量电路与误差因素](https://www.analog.com/en/resources/analog-dialogue/articles/thermistor-temperature-sensing-system-part-1.html)

## 6. 已观察到的改善与热模型解释

可用一个简化的探头热网络理解方向。以下是推导模型，**不是本机已识别参数**：

```text
Cs × dTs/dt = Gm × (Tm − Ts) + Gh × (Th − Ts)
              + Ga × (Ta − Ts) + Ps
```

`Ts`为探头温度，`Tm`为目标液温，`Th`为旁路热源温度，`Ta`为环境温度；`Gm/Gh/Ga`是相应等效热导（热阻的倒数），`Cs`是探头等效热容量，`Ps`是探头自热功率。实际结构可能需要多节点模型。

在边界温度缓慢变化、参数近似恒定时：

```text
Ts − Tm ≈ [Gh × (Th − Tm) + Ga × (Ta − Tm) + Ps] / (Gm + Gh + Ga)
探头时间常数 τ ≈ Cs / (Gm + Gh + Ga)
```

因此应尽量提高`Gm`、降低不希望存在的`Gh`，而不是笼统地给整个探头包上隔热层。外部隔热层也可能改变`Cs`，不能只看热阻。

**纯示例：** 忽略环境和自热，假设`Gh/Gm=1/9`，热源比液体高30℃，则探头受旁路热源影响的偏差为`30×0.1=3℃`。若仅将旁路热阻提高5倍、其余不变，偏差为`30/46≈0.65℃`，该误差分量约减小78.3%。这是说明传热路径的假设算例，既不是本机预测，也不是整体测温误差降低78.3%。实际旁路温度也可能随改造变化。

相反，同一假设下若误把“液体到探头”的热阻提高5倍，旁路热影响比例会从0.1升至约0.357，偏差反而约为10.7℃，响应也更慢。

**结合已加强隔热和补偿差值反馈的判断：**

- 用户反馈的约10℃补偿差值是目前最直接的本机改善线索；它与下述假设算例无关，不应用算例反推本机热阻。

- 若剩余偏差主要随加热功率、加热盘余热变化，且原始NTC相对参考探头存在明显局部超温，正确的旁路隔热可能带来较大收益。
- 若当前相同工况下的误差已经很小，主要问题是换水量、换节拍或换样机后偏差变大，则收益主要体现在工况适应性和一致性。
- 若问题主要是电气跳点、参考探头偏差、液体分层或滤波滞后，单纯隔热的收益可能很小，甚至改变热边界后破坏现有补偿。

当前已知升温补偿前后差值约10℃，但没有各误差分量的独立测量，不能进一步换算成最终测温误差下降值或热耦合降低比例。

## 7. 如何核实补偿差值及剩余收益

优先整理已经完成的改造前后记录：旧表、新表、参考温度、原始ADC、温区、实际功率及电机节拍。先明确“补偿高约10℃”指相同ADC下表值差、相同真实温度下对基础换算的修正差，还是其他口径；这些比较的含义不同。

若仍能保留原结构样机或做可逆改造，再用同一台机器做A/B对照：A为原结构，B仅改变旁路隔热，保持NTC型号、探头位置和液体接触一致。每个条件至少做3次完整升降温，按交替顺序试验，并用相同初始状态减少热历史影响。若无法恢复原结构，明确记录历史数据与当前实验条件的差异，不把跨批次差异全部归给隔热。

1. 固定液体种类、水量、参考探头位置、搅拌节拍及环境条件；参考测点避开加热面、补水口，并检查液体温度分层。
2. 同时记录三路原始ADC、实际RPM、实际有功功率、加热开关和目标档位、原始与滤波温度、参考温度及时间。标记恢复任务的0档→目标档位事件，避免把它当成结构影响。
3. 在例如60、80、90、95℃附近建立小范围温度窗口，改变实际功率或开停占空比，扣除参考液温本身的变化，观察NTC相对参考的偏差变化。比较功率时保持搅拌状态一致。
4. 将快速电气跳变与随后较慢的温度响应分开观察；时间尺度只用于定位线索，不能单独作为干扰来源的定论。
5. 先冻结旧标定和算法，比较改造前后原始测量关系及现有补偿的表现；旧表在新结构上变差不代表结构变差，可能是旧补偿不再适用。随后为A/B各自用训练批次建表，使用整批独立试验评价最终精度。
6. 不要同时换结构、重做表格和改滤波后，只比较两条显示曲线，否则无法分辨各自贡献。

| 对照指标 | 计算/观察方式 | 用途 |
|---|---|---|
| 功率相关偏差 | `e=T_NTC−T_ref`；匹配温区后比较不同实际功率的`e`，或拟合局部`Δe/ΔP` | 判断旁路受热影响是否减弱；动态数据还需控制升温速度与历史 |
| 升降温回差 | 相同参考温度、相近搅拌条件下比较升温和降温偏差 | 判断是否更接近一条通用换算关系 |
| 响应速度 | 比较相对参考的延迟、加热关断后偏差及温度过冲 | 检查是否因隔热造成响应变慢 |
| 独立批次精度 | 按整批数据留出，分别计算升/降温及分温区MAE、P95和最大绝对误差 | 判断真实泛化精度，不用建表数据代替 |
| 有效性与工艺结果 | 有效采样比例、保持旧值时长、达到98℃的实际液温、降温终点实际液温 | 排除“读数稳定但没有更新”，检查控制结果 |

若要量化每种算法的贡献，可在相同原始数据上逐项关闭分工况补偿、ADC中值、趋势滤波和输出滤波后重放，与相同参考温度比较误差及延迟。阶段管理和采样门控属于有状态处理，应按完整时间线重放。更严格地分离热结构贡献仍需要实物A/B，离线重放不能替代；用户提供的改造前后反馈保留为现场证据。
