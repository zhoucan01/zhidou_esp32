# 当前温度停更路径审查

审查对象：机器3主温度路径，当前 ntcTemp.c 与 DataCenter.c；本次只分析，不修改固件。

## 已由真实生产代码主机复现

1. 运行中双重趋势门控。update_adc_window 先对原始ADC校验，接纳后返回20点中值；machine3_channel_temperature 又拿该中值与当前原始ADC趋势预测比较。以20ms步长、每步增加10 ADC的线性历史为例，新原始值1800通过，中值1705因落后趋势95 ADC超过40阈值被拒绝。持续斜坡下该偏差可持续，出现ADC在动、温度不更新。这是当前新增运行中门控的实现缺陷，应优先改为传递当前原始样本的许可，不把中值当新的原始样本重新鉴别。

2. 运行中历史过期后无自恢复入口。门控只依赖可信ADC历史，最新点超过2秒即拒绝；被拒绝点不会更新可信历史。可信基准2000，电机运行中连续3秒提交2400被拒绝，回到2000也因基准过期而被拒绝。若始终运行且没有停机覆盖，历史不会自动恢复。需单独设计与可信历史隔离的重新接纳证据，而非直接放行旧预测。

3. 短停候选不足。重新接纳要求8点、至少140ms。电机启动调用 ntcTempResetTemperatureTrend 同时清ADC候选；每次停机只有7个候选，再启动清零，模拟20轮后可信中值仍为2000。停机后200ms等待、采样调度、RPM回读延迟及仅5次命令覆盖会共同缩短可用窗口。需要区分电机污染和已验证的停机证据，不能无条件累加跨电机状态的点，也不能无条件丢弃所有候选。

主机探针：agent-tp/tests/firmware/test_temperature_freeze_probe.c，直接包含生产ntcTemp.c，控制时钟与模拟DataPool。编译复现：

```sh
gcc -std=c11 -Wall -Wextra -Werror -DMACHINE=3 -DNTC_TEMP_LOG_ENABLE=0 -Ifunction/ntcTemp -Itask/DataCenter -Iagent-tp/tests/firmware/ntc_host agent-tp/tests/firmware/test_temperature_freeze_probe.c -lm -o build/probe_temperature_freeze
build/probe_temperature_freeze
```

输出：原始1800通过、中值1705拒绝；运行3秒后回到2000仍拒绝；20轮7点候选后可信值2000未变。探针不证明实机当前原因。

## 其他代码可见原因

- 标定覆盖：选不到对应工况/阶段，或ADC超出曲线及有限外推范围时返回NaN；保留本通道旧温度。选表依赖该通道自身最近温度，因此错误的阶段/覆盖不足有维持旧状态的可能，需按实际ADC及曲线范围核对，不能只看最终温度。
- 候选持续不合格：反向、离散、无效ADC、非递增时间、间隔超过2秒、温度残差/速率超限都会延迟重新接纳。各通道独立并不等于每条数据都接受。
- 源头断流：站2读取失败时poll_actuator_registers直接返回，原始ADC和温度均保留旧值；目前不将最终温度标为过期。站3RPM反馈保持非零也会持续采用运行门控。
- 外层滤波与显示平台：DataCenter20点按降序取第4至7名均值，慢速采样时会有明显台阶，不能等同永久停更；输出低于25℃钳25℃、高于100℃钳100℃，97.9至98℃映射98℃也会形成平台。

建议按链路记录每路原始ADC、可信中值、预测/残差、采样年龄、ADC/温度接纳标志、候选数量、所选阶段/工况、查表输出，以及DataCenter最终温度。优先处理上述第1、2项，随后验证短停证据策略。本次未修改生产逻辑、未烧录。
