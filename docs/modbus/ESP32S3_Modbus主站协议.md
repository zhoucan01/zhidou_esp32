# ESP32-S3 Modbus RTU 主站协议

## 1. 文档信息

| 项目 | 内容 |
|---|---|
| 适用设备 | ESP32-S3 主控、站号 2 执行机构板、站号 3 动力板 |
| ESP-IDF 端口 | 站号2=`UART_NUM_2`；站号3=`UART_NUM_1` |
| 协议版本 | V1.29 |
| 更新日期 | 2026-10-26 |
| 协议依据 | `站号2_AT32F415CBT7_Modbus协议.md`、`站号3_STM32G431RBTx_Modbus协议.md` |

本文是 ESP32-S3 主站侧汇总说明；从站寄存器语义以对应站号文档为准。地址均为 Modbus PDU 零基地址，不使用 `40001` 等偏移表示法。

上位机的两种接线及操作步骤见 `串口上位机控制说明.md`。

## 2. 总线与通信参数

| 项目 | 站号 2：执行机构板 | 站号 3：动力板 |
|---|---:|---:|
| 从站地址 | `0x02` | `0x03` |
| 波特率 | 1000000 | 1000000 |
| 数据格式 | 8N1 | 8N1 |
| 寄存器字节序 | 高字节在前 | 高字节在前 |
| CRC | CRC-16/Modbus，低字节在前 | 同左 |
| 广播地址 | 0，只执行写、不应答 | 同左 |
| 支持功能码 | 01、02、03、04、05、06、0F、10 | 同左 |

两个从站使用独立串口：UART2 的 TX=`GPIO1`、RX=`GPIO2`，1000000 8N1，只控制站号2；UART1 的 TX=`GPIO38`、RX=`GPIO39`，1000000 8N1，只控制站号3。两端均使用二线 RS-485，DE 分别接 GPIO36、GPIO37，并由 UART RTS 在 `UART_MODE_RS485_HALF_DUPLEX` 模式下自动控制。

## 3. RTU 帧和通用规则

```text
从站地址(1) + 功能码(1) + 数据(N) + CRC低字节(1) + CRC高字节(1)
```

- 单线圈开启值为 `0xFF00`，关闭值为 `0x0000`。
- 单寄存器为 16 位；有符号值按 `int16_t` 二进制补码传输。
- `float32` 使用 ABCD 字序：低地址保存 IEEE754 高 16 位。例如 `1.0` 为 `3F80 0000`。
- 固件版本 `0x000B～0x000C` 的四个数值字节如 `00 00 00 01` 表示 `0.0.0.1`，不是 ASCII 字符串。
- 错站号或 CRC 错误时无应答；异常功能码为请求功能码加 `0x80`。常见异常码：`01` 非法功能、`02` 非法地址、`03` 非法值、`04` 设备故障、`06` 从站忙。

## 4. 站号 2：执行机构板

### 4.1 线圈（01/05/0F）

| 地址 | 对象 | 0 | 1 | ESP32 处理 |
|---:|---|---|---|---|
| `0x0000` | 清水泵 | 停止 | 100%运行 | 启动前写速度 |
| `0x0001` | 点卤泵 | 停止 | 运行 | 直接控制 |
| `0x0002` | 蠕动泵 | 停止 | 80档运行 | 启动前写速度 |
| `0x0003` | 阀门 | 关闭 | 开启 | 直接控制 |
| `0x0004` | LED | 关闭 | 开启 | 直接控制 |
| `0x0005～0x0007` | 预留执行器 | 保存状态 | 保存状态 | 不赋予业务语义 |
| `0x0008` | 压制电机命令状态 | 停止 | 运行 | 状态镜像，只读使用 |
| `0x0009` | 抬升电机命令状态 | 停止 | 运行 | 状态镜像，只读使用 |

主站读取 `0x0000` 起的 10 个线圈。压制/抬升只通过保持寄存器 `0x0002/0x0003` 控制，不写线圈 8/9。

### 4.2 离散输入（02）

主站支持读取 FC02 地址 `0x0000～0x0011` 共 18 个离散输入，不反相。地址 `0x0000～0x000F` 来自输入寄存器 `0x000E` 的低位图；新增地址 `0x0010/0x0011` 来自输入寄存器 `0x004F` 的 bit0/bit1。读取应答按 Modbus 位序排列：每个数据字节的 bit0 对应较小地址，先低字节位，再高字节位。

最新协议中 bit0/bit1 恢复为抬升**合并高位/合并低位**；左右两侧高位实际开关状态移到 bit14/bit15。合并高位（地址 `0x0000`）在上行过程中表示左右均到位并锁存，静止时要求两侧开关同时触发；合并低位（地址 `0x0001`）由编码器下行到位判断。左高实际状态（bit14）来自 PF6，右高实际状态（bit15）来自 PA15。

| 地址 | 内容 | 软件枚举 |
|---:|---|---|
| `0x0000` | 抬升合并高位 | `riseHighPos` |
| `0x0001` | 抬升合并低位（编码器下行到位） | `riseLowPos` |
| `0x0002` | 压制高位 | `pressHighPos` |
| `0x0003` | 压制低位 | `pressLowPos` |
| `0x0004` | 压制头在位 | `pressHeadAvail` |
| `0x0005` | 水箱在位 | `waterBoxAvail` |
| `0x0006` | 水箱高液位 | `waterBoxHighPos` |
| `0x0007` | 水箱低液位 | `waterBoxLowPos` |
| `0x0008` | 废水箱在位 | `wasteBoxAvail` |
| `0x0009` | 阀门开到位 | `valveOnPos` |
| `0x000A` | 阀门关到位 | `valveOffPos` |
| `0x000B` | 点卤盒在位 | `brineBoxAvail` |
| `0x000C` | 溢出报警 | `overFlow` |
| `0x000D` | 上盖在位 | `lidAvail` |
| `0x000E` | 抬升左高实际状态（PF6） | `riseLeftHighPos` |
| `0x000F` | 抬升右高实际状态（PA15） | `riseRightHighPos` |
| `0x0010` | 点卤盒在位（D0 `brineLowPos`） | `brineLowPos` |
| `0x0011` | 成型通道在位（D1 `modeAvail > 0`） | `modeAvail` |

### 4.3 保持寄存器（03/06/10）

| 地址 | 内容 | 类型与范围 | ESP32 行为 |
|---:|---|---|---|
| `0x0000` | 清水泵速度 | `uint16_t`，0～1000 | 超限按 1000 发送 |
| `0x0001` | 蠕动泵速度 | `uint16_t`，0～255 | API 限制为 0～255 |
| `0x0002` | 压制有符号速度 | `int16_t`；正=Up，负=Down，0=Stop | 方向和速度合并编码 |
| `0x0003` | 抬升有符号命令 | `int16_t`；正=Up，负=Down，0=Stop | 当前从站不按绝对值调速 |
| `0x0004～0x0066` | 参数/预留区 | RAM，上电清零 | 不赋予控制语义 |

例如 `+23=0x0017`、`-23=0xFFE9`。清水泵/蠕动泵启动作为一个队列命令执行：速度写成功后才开线圈，避免按旧速度启动。

### 4.4 输入寄存器（04）

主站使用功能码 `04` 一次读取 `0x0000～0x004F` 的 80 个寄存器（含V2追加区），从同一份从站快照解析测量值、执行器状态、底层输入和通信诊断信息，不再另外轮询线圈和离散输入。站号2 V2 固件在 `0x004F` 提供离散输入高位图；标准型从站（非V2主板）的 `0x0028～0x004F` 返回 0，不影响解析。

| 地址 | 内容 | 主站字段 |
|---:|---|---|
| `0x0000～0x0001` | 温度 `float32`（主站换算值，见下） | `temperature` |
| `0x0002～0x0003` | 母线电压 `float32` | `voltage` |
| `0x0004～0x0005` | 电流 `float32` | `current` |
| `0x0006` | 抬升电机设定镜像 | `speed`（`int16_t`） |
| `0x0007～0x0008` | 累计圈数 `float32` | `turns` |
| `0x0009` | 设备状态字 | `statusWord` |
| `0x000A` | 故障码 | `faultCode` |
| `0x000B～0x000C` | 固件版本 | `version[1]` |
| `0x000D` | 保留 | 忽略 |
| `0x000E` | 16 个低位离散输入位图 | `sensorState[0..15]`；bit0/1=抬升合并高/低位，bit14/15=左/右高实际状态 |
| `0x000F` | 10 个线圈命令状态位图 | `moterState[]` / `actuatorCoilBitmap` |
| `0x0010～0x0013` | 清水泵、蠕动泵、压制电机、抬升电机命令镜像 | 对应 `*Command` 字段 |
| `0x0014` | 旧协议/协议接收队列深度 | `legacyQueueDepth` / `modbusQueueDepth` |
| `0x0015～0x001C` | 四组 `uint32_t` 通信异常累计计数，高字在前 | 对应诊断计数字段 |
| `0x001D～0x001E` | TMUX1308 D0/D1 原始数字输入位图 | `tmuxD0Bitmap` / `tmuxD1Bitmap` |
| `0x001F～0x0026` | TMUX1308 通道 0～7 原始 ADC | `tmuxAdcRaw[]` |
| `0x0027` | 板载电流采样 ADC 原始值 | `currentAdcRaw` |
| `0x004F` | 站号2离散输入高位图，bit0/bit1 对应 FC02 地址 `0x0010`/`0x0011` | `actuatorDiscreteBitmapHigh`；同时映射到 `sensorState[16..17]` |

温度换算说明：主站读取从站快照 `0x0041～0x0042`（NTC2 原始 ADC 值，uint32），经 `function/ntcTemp` 标定模块换算后存入 ESP32 专用字段 `g_DataPool.temperature`（通过 `getTemp()` 访问），同时站号1摘要 `0x000C～0x000D` 也输出该转换后的温度。快照寄存器 `0x0041～0x0042` 保持从站原始值不变。ESP32 侧所有温度消费方（`getTemp()`、DryBoil 防干烧、站号1摘要）读到的都是 NTC2 标定温度。换算为单张单调表 + 二分查找 + 线性插值，无档位/状态维度；当前表覆盖 ADC 1622.628～3371.885（对应 99.6～41.7℃，2026-10-12 重新标定）：计算温度在[97.9, 98.0)°C 时映射为 98.0°C，计算温度达到或超过 98.0°C 时保留原值；ADC 超出表端点时钳到该端点温度（室温下 ADC 高于表上限，会恒定显示 41.7°C，属标定范围外夹紧），可用 `ntcTempIsInRange()` 判断是否落在标定范围内；NTC1 保留原始值并另有一套独立拟合（`ntcTempGetNtc1Temperature()`）。NTC1/NTC3/NTCBack 不做主温度换算，快照 `0x0000～0x0001`、`0x0043～0x0044`、`0x0045～0x0046` 直接显示和保存原始值。标定数据来源与精度见 `function/ntcTemp/README.md`。

## 5. 站号 3：动力板

电机、下加热和上加热是独立通道，总开关打开后可同时运行。控制类型/模式和独立方向寄存器已删除。ESP32 高层控制 API 在下发非零档位前会先写总开关 `0x0000=1`，以保持旧业务调用的启动语义；也可调用 `setPowerEnabled(false)` 关闭总开关并由从站清空全部档位。

### 5.1 线圈（01/05/0F）

| 地址 | 内容 | 0 | 1 |
|---:|---|---|---|
| `0x0000` | 总开关 | 关闭并清空全部档位 | 打开 |
| `0x0001～0x0009` | 保留 | 无控制作用 | 无控制作用 |

总开关的实际控制使用保持寄存器 `0x0000`；ESP32 不向站号 3 写线圈。

### 5.2 离散输入（02）

`0x0000` 为总开关状态，`0x0001` 为下加热状态，`0x0002` 为上加热状态，`0x0003～0x000F` 保留。主站通过完整输入寄存器快照取得运行状态，不再额外轮询此区。

### 5.3 保持寄存器（03/06/10）

| 地址 | 内容 | 类型与范围 | ESP32 行为 |
|---:|---|---|---|
| `0x0000` | 总开关 | 0=关闭且清空三路档位，1=打开 | 非零档位前自动打开，支持显式关闭 |
| `0x0001` | RAM 参数 | 无控制语义，上电清零 | 不写 |
| `0x0002` | 下加热档位 | 0～30 | 输入收敛到 0～30 |
| `0x0003` | 上加热档位 | 0～30 | 输入收敛到 0～30 |
| `0x0004` | 有符号电机档位 | `int16_t`，-15～15 | 正转为正、反转为负、0停止 |
| `0x0005～0x0030`、`0x0033～0x003F` | RAM 参数区 | 无控制语义 | 不写 |
| `0x0031` | 直接周波阈值 | 0～65535，且不大于 `0x0032` | 由上位机FC10成组设置 |
| `0x0032` | 直接周波总数 | 1～65535，且不小于 `0x0031` | 由上位机FC10成组设置 |
| `0x0040～0x006B` | 扩展状态快照 | 只读 | 读取当前诊断和运行状态 |

`NoBushRun(gear)` 接受有符号档位并收敛到 `-15～15`。兼容接口 `setPowerMotor(gear, direction)` 将绝对档位和方向编码成一个 `int16_t`；非零命令先写总开关，再写 `0x0004`。
站3输入快照在 `0x0015` 后追加电表频率 `0x0016～0x0017`，并将站3保持寄存器周波阈值/总数 `0x0031/0x0032` 镜像到快照 `0x0018/0x0019`。站1 FC04 的站3镜像 `0x0200～0x0219` 对应完整的站3快照 `0x0000～0x0019`。

### 5.4 输入寄存器（04）

| 地址 | 内容 | 主站字段 |
|---:|---|---|
| `0x0000` | 电机实际转速 RPM（绝对值） | `powerMotorRpm` |
| `0x0001` | MCSDK 电机状态 | `powerMotorState` |
| `0x0002` | 电机相电流幅值（0-to-peak），mA | `powerMotorPhaseCurrentMa` |
| `0x0003` | 总开关状态 | `powerEnabled` |
| `0x0004～0x0005` | 下/上加热开关状态 | `powerHeater1Enabled` / `powerHeater2Enabled` |
| `0x0006～0x0007` | 下/上加热当前档位 | `powerHeater1Gear` / `powerHeater2Gear` |
| `0x0008` | 电机当前有符号档位 | `powerMotorGear` |
| `0x0009～0x000A` | 保留，当前返回 0 | 忽略 |
| `0x000B～0x000C` | 固件版本 | `version[2]` |
| `0x000D` | 保留 | 忽略 |
| `0x000E` | PC2/ADC2_IN8 中值 | `powerPc2AdcMedian` |
| `0x000F～0x0010` | 电表电压（32 位无符号，mV，高字在前） | `powerMeterVoltageMv` |
| `0x0011～0x0012` | 电表电流（32 位无符号，mA，高字在前） | `powerMeterCurrentMa` |
| `0x0013～0x0014` | 电表有功功率（32 位无符号，mW，高字在前） | `powerMeterActivePowerMw` |
| `0x0015` | 电表采样有效标志，1=有效 | `powerMeterSampleValid` |
| `0x0016～0x0017` | 电表频率（32 位无符号，mHz，高字在前） | `powerMeterFrequencyMilliHz` |
| `0x0018` | 周波阈值，镜像站3保持寄存器 `0x0031` | `powerCycleThreshold` |
| `0x0019` | 周波总数，镜像站3保持寄存器 `0x0032` | `powerCycleTotal` |

`moterState[breakMoter]` 由实际 RPM 是否非零推导，不再错误读取站号 2 的预留线圈 7。
站号3后台每次读取 FC04 `0x0000～0x0017` 共24个输入寄存器，并读取 FC03 保持寄存器 `0x0031/0x0032` 及校准状态；上述读取均成功后才一起更新快照。最终组合成 `0x0000～0x0019` 共26个站3缓存快照寄存器，周波阈值/总数来自本轮保持寄存器读取。

## 7. 主站调度与容错

- 业务命令进入 32 项线程安全队列并优先执行；队列满时拒绝新命令并记录日志。
- 写失败会重试；读失败保留上次有效数据，后续轮询自动恢复。
- 后台按独立周期采集两个从站：站号2每20 ms读取80个输入寄存器（含V2追加区）的完整快照，站号3每100 ms读取24个原生输入寄存器及周波配置，组合成26个寄存器的站3快照；上位机透传、业务写命令或从站超时占用队列时按顺序顺延。
- 上位机透传、内部业务写入和后台轮询都进入同一个线程安全队列，最终只由 `DataCenterTask` 逐条执行。
- 每个队列项带 `reply_to_debug` 标志：上位机 `MODBUS-TX` 请求为 `true`，后台轮询和内部业务命令为 `false`。只有前者将应答交给调试任务输出。
- 所有收发按站号选择专用 UART；即使轮询触发时同时收到上位机请求，也只会形成两个有序队列项，不会并发发送或串读应答。
- 动力板三路独立写入，修改一路不会覆盖另外两路；档位发送前均限幅。
- 采集测试模式：串口发送 `TEST:02`/`TEST:03`/`TEST:END`/`TEST:STATS` ASCII命令，停止自动轮询并以最快速度连续读取指定从站全部输入寄存器，统计成功/超时/CRC错误/非法响应次数及单次耗时。详见 `docs/串口上位机控制说明.md` §6。

## 10. UART0 Modbus 字符串网关协议

ESP32 同时具有两个角色：对 UART0 上位机是地址 `0x01` 的 Modbus 从站；对设备地址 `0x02/0x03` 是 Modbus 主站。

调试口使用 UART0、115200、8N1。每行格式为：

```text
MODBUS-TX:[<完整Modbus RTU请求帧的十六进制字符串>]<CR/LF>
```

要求如下：

- `MODBUS-TX:[` 不区分大小写，前面允许空格；必须以 `]` 结束，没有完整首尾标记的文本直接忽略或报格式错误。
- 每个字节必须写成两位十六进制，字节间至少一个空白字符。
- 输入必须包含正确的 CRC16，顺序仍为 CRC低字节、CRC高字节。
- UART0使用流式状态机识别首尾标记，不保存完整文本行；RTU帧最大为256字节。
- 站号1、2、3的成功应答统一输出为 `MODBUS-RX:[XX XX ... CRC_L CRC_H]`。
- 只有由 `MODBUS-TX` 触发的应答才输出；ESP32后台轮询应答不输出。
- UART0 同时输出系统日志，因此应答可能和普通日志交错；上位机只提取以 `MODBUS-RX:` 开头的行。

### 10.1 路由规则

| RTU地址 | 处理方式 |
|---:|---|
| `0x02` | 原始帧通过 UART2、1000000 下发；本次应答格式化为 `MODBUS-RX:[...]` 返回 |
| `0x03` | 原始帧通过 UART1（TX=IO38、RX=IO39）、1000000 下发；本次应答格式化为 `MODBUS-RX:[...]` 返回 |
| `0x01` | ESP32 本地从站处理，不发送到设备串口 |
| 其他 | 返回 `ERROR:SLAVE` |

站号2/3请求、后台轮询和业务写命令进入同一队列并由 `DataCenterTask` 串行执行。上位机请求的 `reply_to_debug=true`，其RTU应答经校验后返回UART0；轮询及业务命令为 `false`，应答仅在ESP32内部消费。

### 10.2 网关层错误

| 文本响应 | 含义 |
|---|---|
| `ERROR:FORMAT` | 十六进制格式或帧长度错误 |
| `ERROR:CRC` | 请求CRC错误 |
| `ERROR:SLAVE` | 地址不是1、2、3 |
| `ERROR:TIMEOUT` | 站号2/3下发后无应答或本地队列提交失败 |
| `ERROR:RESPONSE_CRC` | 站号2/3应答CRC错误，损坏的原始帧不输出 |
| `ERROR:FRAME_TOO_LONG` | 方括号内解码后的RTU帧超过256字节 |

站号1收到合法 RTU 请求但功能码、地址或数值非法时，返回标准 Modbus 异常帧，而不是 `ERROR:` 文本。

### 10.3 站号1本地寄存器

站号1支持功能码 `03`、`04`、`06`、`10`。保持寄存器 `0x0000～0x000F` 是本机调试 RAM，支持读写且不触发机械动作；`0x0010` 是显示帧率设置；`0x0011` 是站3电机方向限制；`0x0100` 是流程命令寄存器。

| 保持寄存器地址 | 内容 |
|---:|---|
| `0x0000～0x000F` | 本机调试RAM，上电清零，无业务副作用 |
| `0x0010` | LVGL目标刷新帧率，`uint16`，范围`1～20` FPS，上电默认`10`，掉电不保存 |
| `0x0011` | 站3电机方向限制，`uint16`：0=不限制，1=只能正转，2=只能反转；上电默认0，掉电不保存 |
| `0x0100` | 流程命令，仅支持功能码`06`写入 |

写`0x0010`成功后立即调整LVGL任务调用周期；写`0x0011`后立即影响后续站3电机转速命令，现有运行中的转速命令不会被追写。两者均可通过功能码`03`读回当前值；非法值返回异常码`03`且不改变原设置。方向限制只约束 ESP32 的 `setPowerMotor()` 控制入口，不会改写通过 `MODBUS-TX` 透传的站3原始报文。功能码`10`写入包含`0x0010`或`0x0011`的连续区域时先校验全部数据，校验失败则整条请求均不生效。

方向限制使用站号1的 FC06（写单个保持寄存器）设置。请求前缀 `01 06 00 11` 依次表示：目标站号 `01`、功能码 `06`、保持寄存器地址 `0x0011`；后续两个字节是设置值，`00 00`=不限制、`00 01`=只正转、`00 02`=只反转，最后两个字节为 CRC（低字节在前）。例如 `01 06 00 11 00 01 18 0F` 表示设置为只允许正转；成功时从站1原样回显整帧。这里的 `0x0011` 属于站号1保持寄存器地址空间，与站号2 FC02 的离散输入地址 `0x0011`（成型通道在位）不是同一个寄存器。

| 输入寄存器地址 | 内容 |
|---:|---|
| `0x0000～0x0001` | ESP32固件版本，依次为主、次、修订、构建各1字节；`0.0.0.3`返回`00 00 00 03` |
| `0x0002` | 本机站号，固定 `0x0001` |
| `0x0003` | 网关协议版本，V1.29=`0x010A` |
| `0x0004` | 站号2状态字 |
| `0x0005` | 站号2故障码 |
| `0x0006` | 站号3电机实际RPM |
| `0x0007` | 站号3 MCSDK状态 |
| `0x0008` | 站号3状态位：bit0下加热、bit1上加热、bit2总开关 |
| `0x0009` | 站号2 FC02 地址 `0x0000～0x000F` 位图，bit 与地址低位优先 |
| `0x000A` | 站号2 FC02 地址 `0x0010～0x0011` 位图，bit0/bit1 对应地址 `0x0010`/`0x0011` |
| `0x000B` | ESP32业务执行器状态位图 |
| `0x000C～0x000D` | 温度 `float32`（NTC1），ABCD字序 |
| `0x000E～0x000F` | 母线电压 `float32`，ABCD字序 |
| `0x0010～0x0011` | 电流 `float32`，ABCD字序 |
| `0x0012` | 当前流程号：`0x51～0x56`，无流程为 `0` |
| `0x0013` | 当前流程动作：开始=`1`、暂停=`2`、恢复=`4`，无流程为 `0` |
| `0x0014～0x0015` | PSRAM 当前可分配的8位堆余量，`uint32`，字节，高字在前 |
| `0x0016～0x0017` | 内部 RAM 当前可分配的8位堆余量，`uint32`，字节，高字在前 |
| `0x0018～0x0019` | 最近完整1秒窗口内完成的刷新帧数，`uint32`，高字在前；数值也为FPS |
| `0x001A～0x001B` | 同一窗口平均刷新耗时，`uint32`，微秒，向下取整，高字在前 |
| `0x001C～0x001D` | 同一窗口最大刷新耗时，`uint32`，微秒，高字在前 |
| `0x001E～0x0020` | 蓝牙 MAC 地址，6 字节，每寄存器高字节在前；`MB_LOCAL_INPUT_BLUETOOTH_MAC_COUNT=3` |
| `0x0021` | 站3电机方向限制模式快照：0=不限制，1=只正转，2=只反转；与保持寄存器 `0x0011` 当前值相同 |
| `0x0100～0x014F` | 站号2最近一次完整输入寄存器快照，依次镜像站号2的 `0x0000～0x004F`（含V2追加区） |
| `0x0200～0x0219` | 站号3最近一次完整缓存快照，依次镜像逻辑地址 `0x0000～0x0019`；其中 `0x0218/0x0219` 为周波阈值/总数 |

站号3必须运行支持输入寄存器 `0x0017` 和保持寄存器 `0x0031/0x0032` 的固件。任一部分读取失败时保留上一份完整快照。

`0x0100` 和 `0x0200` 两个区域只读取 ESP32 RAM，不会向站号2/3发送临时查询，因此上位机应优先轮询这两个区域。ESP32 后台仍负责更新缓存。设备刚启动、对应站尚未成功完成第一次轮询时，读取其缓存返回 Modbus 异常 `01 84 04`（从站设备故障），并紧跟一行诊断信息 `CACHE:STATION=02 NOT_READY` 或 `CACHE:STATION=03 NOT_READY` 标明是哪个站缓存未就绪；成功取得首份快照后即可读取。每次响应来自同一份完整快照，不会混入正在更新的半帧数据。

站号1读取 `0x0009～0x000A` 可同时取得站号2全部18个离散输入状态：`0x0009` 的 bit0～bit15 对应 FC02 地址 `0x0000～0x000F`，`0x000A` 的 bit0/bit1 对应 FC02 地址 `0x0010/0x0011`，其余位为0。也可直接对站号2使用 FC02 读取18个状态；开机后第一次站号2快照尚未就绪时，建议稍后重试。

内存余量在查询时采集，表示空闲堆总量，不是最大连续空闲块。显示统计从显示初始化开始使用固定1秒窗口，按最后一块DMA完成时刻归入窗口；从LVGL开始绘制脏区域计时，到最后一块DMA完成结束，包括绘制、传输、等待和调度时间。一次局部或整屏刷新均计一帧，不按DMA块数计帧。窗口无刷新时帧数/平均/最大耗时均为0；启动未满1秒时显示统计为0。一次响应中的三个显示字段来自同一快照，查询不清零，建议每秒查询一次；静态画面FPS为0是正常的。这些字段不是CPU或PSRAM利用率。

完整摘要状态读取使用起始地址`0x0000`、数量`0x0024`（36），应答开头为`01 04 48`，共72字节数据，RTU帧共77字节。方向模式、周波阈值和总数也可分别从 `0x0021～0x0023` 读取。诊断字段按`(high << 16) | low`解析，耗时除以1000得到毫秒。`0x0024～0x00FF`不提供输入寄存器，跨越空洞读取返回异常码`02`。站号2/3完整缓存仍单独读取。

## 11. 站号1 Modbus流程控制

站号1保持寄存器 `0x0100` 为流程命令寄存器，仅支持功能码 `06` 写入。值的高字节为功能号 `51～56`，依次对应豆浆、压制、豆腐、植物奶、自清洁、豆腐脑/点卤；低字节 `01/02/04/08` 依次表示开始、暂停、恢复、停止。例如 `MODBUS-TX:[01 06 01 00 51 01 74 66]` 启动豆浆流程。

该入口严格限制为流程命令，不提供单独外设控制。站号2/3的泵、电机和加热等控制继续使用原来的 Modbus 地址。合法命令成功入队后返回标准功能码06回显；非法值返回异常码03，队列忙返回异常码06。保持寄存器 `0x0100` 可用功能码03读回最近一次成功接收的流程命令。

站号1输入寄存器 `0x0012` 返回当前流程号，`0x0013` 返回当前动作；读取帧为 `MODBUS-TX:[01 04 00 12 00 02 D1 CE]`。停止后两个寄存器均为0。
