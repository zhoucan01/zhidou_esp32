# 串口上位机控制说明

| 项目 | 内容 |
|---|---|
| 适用设备 | ESP32-S3网关、站号2执行机构板、站号3动力板 |
| 更新日期 | 2026-10-14 |
| 地址规则 | 本文地址均为Modbus PDU零基地址 |
| 协议依据 | `站号2_AT32F415CBT7_Modbus协议.md`、`站号3_STM32G431RBTx_Modbus协议.md` |

> 从站控制语义以对应站号专用文档为准。当前站号3专用文档的最后变更为“恢复总开关”，因此站号3启动电机或加热前必须先打开保持寄存器`0x0000`。

## 1. 控制方式总览

上位机有三种连接方式，发送格式不能混用。

| 模式 | 上位机连接对象 | 串口参数 | 上位机发送模式 | 数据格式 |
|---|---|---|---|---|
| 通过 ESP32 控制 | ESP32 调试口 UART0 | 115200、8N1 | ASCII/文本 | 请求`MODBUS-TX:[...]`，应答`MODBUS-RX:[...]` |
| 直接控制站号2 | AT32F415CBT7 USART1 | 1000000、8N1 | HEX/二进制 | 原始 Modbus RTU 帧 |
| 直接控制站号3 | STM32G431RBTx UART2 | 1000000、8N1 | HEX/二进制 | 原始 Modbus RTU 帧 |

所有 Modbus RTU 帧都必须包含 CRC16，发送顺序为 CRC低字节、CRC高字节。

## 2. 通过 ESP32 控制

### 2.1 连接与上位机设置

1. 上位机连接 ESP32 的默认调试串口（UART0对应的USB转串口/COM口）。
2. 串口设置为 115200、8位数据位、1位停止位、无校验、无流控。
3. 上位机选择“字符串发送”或“ASCII发送”，不能选择HEX发送。
4. ESP32收到`]`即处理一帧；末尾的CR、LF或CRLF可选。

ESP32启动调试串口后，每10秒主动发送一次心跳：

```text
HEARTBEAT:[10000]
```

方括号中的数值是ESP32启动后的毫秒数。心跳只用于确认调试串口和程序仍在运行，不进入Modbus队列，也不表示站号2或站号3在线。

字符串格式固定为：

```text
MODBUS-TX:[XX XX XX XX]
```

ESP32按字符流识别 `MODBUS-TX:[` 和 `]`，只缓存解码后的RTU字节，不保存整行文本；最大RTU帧长度为256字节。

方括号内是完整的 Modbus RTU 帧，包括从站地址、功能码、数据和CRC。例如原始RTU帧：

```text
02 05 00 04 FF 00 CD C8
```

通过ESP32发送时应输入：

```text
MODBUS-TX:[02 05 00 04 FF 00 CD C8]
```

### 2.2 地址路由

| 地址 | ESP32处理方式 | 调试口正常响应 |
|---:|---|---|
| `0x01` | ESP32本地执行 | 返回 `MODBUS-RX:[...]` |
| `0x02` | 通过UART2、1000000下发给站号2 | 本次应答返回 `MODBUS-RX:[...]` |
| `0x03` | 通过UART1（TX=IO38、RX=IO39）、1000000下发给站号3 | 本次应答返回 `MODBUS-RX:[...]` |

ESP32只返回由上位机 `MODBUS-TX` 请求直接触发的应答；后台轮询、上位机透传和普通业务控制使用同一发送队列，但轮询和业务项不会打印应答。出现超时或CRC错误时可能返回：

```text
ERROR:TIMEOUT
ERROR:RESPONSE_CRC
```

完整网关错误如下：

| 响应 | 含义 |
|---|---|
| `ERROR:FORMAT` | 十六进制格式错误或帧过短 |
| `ERROR:CRC` | 请求帧CRC错误 |
| `ERROR:SLAVE` | 地址不是`0x01`、`0x02`或`0x03` |
| `ERROR:TIMEOUT` | 站号2/3无应答、串口事务失败或队列忙 |
| `ERROR:RESPONSE_CRC` | 站号2/3返回帧CRC错误 |
| `ERROR:FRAME_TOO_LONG` | 解码后的RTU帧超过256字节 |

普通日志和心跳可能与协议响应同时出现在UART0。上位机应按完整行提取`MODBUS-RX:[...]`，不要把日志或`HEARTBEAT`当成Modbus数据。

### 2.3 Modbus控制站号1触发ESP32流程

站号1保持寄存器 `0x0100` 是流程命令寄存器，只支持功能码 `06` 单寄存器写入。寄存器高字节为功能号，低字节为动作。该寄存器只接受流程控制；站号2和站号3的单独设备控制仍使用原有 `MODBUS-TX:[...]`。

| 功能号 | 流程 |
|---:|---|
| `0x51` | 豆浆 |
| `0x52` | 压制 |
| `0x53` | 豆腐 |
| `0x54` | 植物奶 |
| `0x55` | 自清洁 |
| `0x56` | 豆腐脑/点卤 |

| 动作 | 数值 |
|---|---:|
| 开始 | `0x01` |
| 暂停 | `0x02` |
| 恢复 | `0x04` |
| 停止 | `0x08` |

例如启动豆浆流程，寄存器值为 `0x5101`：

```text
MODBUS-TX:[01 06 01 00 51 01 74 66]
```

成功时返回与请求相同的标准功能码06响应。非法功能号或动作返回 Modbus 异常码 `03`，控制队列忙返回异常码 `06`。命令最终进入与蓝牙共用的流程控制队列。

站号1输入寄存器 `0x0012～0x0013` 用于判断当前流程：

| 地址 | 内容 |
|---:|---|
| `0x0012` | 当前流程号：`0x51～0x56` 对应上表，`0` 表示无流程 |
| `0x0013` | 当前动作：`1` 开始、`2` 暂停、`4` 恢复；无流程时为 `0` |

读取命令：

```text
MODBUS-TX:[01 04 00 12 00 02 D1 CE]
```

### 2.4 设置ESP32显示帧率

站号1保持寄存器`0x0010`用于设置LVGL目标刷新帧率。上电默认值为`10` FPS，允许范围为`1～20` FPS，写入成功后立即生效且掉电不保存。

| 操作 | 上位机发送字符串 | 正常结果 |
|---|---|---|
| 设置为最高20 FPS | `MODBUS-TX:[01 06 00 10 00 14 88 00]` | 原样回显请求帧 |
| 读取当前帧率 | `MODBUS-TX:[01 03 00 10 00 01 85 CF]` | 数据区返回当前FPS，例如20返回`00 14` |

使用功能码`06`写单个寄存器，也可使用功能码`10`在包含该地址的连续区域内写入。写入`0`或大于`20`的值时返回异常响应`01 86 03 02 61`（异常码`03`，非法数据值），原帧率保持不变。

该值是LVGL任务的目标调用频率，实际调度会受FreeRTOS时基、页面是否产生脏区以及LCD DMA耗时影响。静态页面即使目标帧率为30，实际完成帧数也可能为0；上位机应读取输入寄存器`0x0018～0x0019`取得最近完整1秒窗口的实际刷新帧数。

### 2.5 通过ESP32控制站号2

| 操作 | 上位机发送字符串 |
|---|---|
| 开启LED | `MODBUS-TX:[02 05 00 04 FF 00 CD C8]` |
| 关闭LED | `MODBUS-TX:[02 05 00 04 00 00 8C 38]` |
| 清水泵速度设为1000 | `MODBUS-TX:[02 06 00 00 03 E8 89 47]` |
| 清水泵停止 | `MODBUS-TX:[02 06 00 00 00 00 89 F9]` |
| 压制电机Up 23 | `MODBUS-TX:[02 06 00 02 00 17 68 37]` |
| 压制电机Down 23 | `MODBUS-TX:[02 06 00 02 FF E9 A8 47]` |
| 压制电机停止 | `MODBUS-TX:[02 06 00 02 00 00 28 39]` |
| 抬升电机Up 23 | `MODBUS-TX:[02 06 00 03 00 17 39 F7]` |
| 抬升电机Down 23 | `MODBUS-TX:[02 06 00 03 FF E9 F9 87]` |
| 抬升电机停止 | `MODBUS-TX:[02 06 00 03 00 00 79 F9]` |

清水泵的完整启动流程是先写保持寄存器0设置速度，再写线圈0开启。例如速度1000后再发送：

```text
MODBUS-TX:[02 05 00 00 FF 00 8C 09]
```

### 2.6 通过ESP32控制站号3

站号3当前恢复了总开关。首次启动电机或任一路加热前，先将保持寄存器`0x0000`写为1；关闭总开关会停止三路输出并清零`0x0002～0x0004`。

| 操作 | 上位机发送字符串 |
|---|---|
| 总开关打开 | `MODBUS-TX:[03 06 00 00 00 01 49 E8]` |
| 总开关关闭 | `MODBUS-TX:[03 06 00 00 00 00 88 28]` |
| 电机正转5档 | `MODBUS-TX:[03 06 00 04 00 05 09 EA]` |
| 电机反转5档 | `MODBUS-TX:[03 06 00 04 FF FB C9 9A]` |
| 电机停止 | `MODBUS-TX:[03 06 00 04 00 00 C9 E9]` |
| 下加热5档 | `MODBUS-TX:[03 06 00 02 00 05 E9 EB]` |
| 上加热5档 | `MODBUS-TX:[03 06 00 03 00 05 B8 2B]` |

总开关打开后，电机档位范围为`-15～15`，正数正转、负数反转、0停止；上下加热档位范围为`0～13`，0停止。三个通道互相独立。

例如站号3上电后启动下加热1档，依次发送：

```text
MODBUS-TX:[03 06 00 00 00 01 49 E8]
MODBUS-TX:[03 06 00 02 00 01 E8 28]
```

总开关保持打开期间，后续调档只需写目标档位寄存器，不需要重复打开总开关。不要使用线圈控制总开关。

### 2.7 访问ESP32自身（站号1）

读取ESP32的全部36个聚合状态输入寄存器（`0x0000～0x0023`，包含流程、内存余量、显示统计、固件版本、蓝牙MAC、电机方向限制和周波配置快照）：

```text
MODBUS-TX:[01 04 00 00 00 24 F0 11]
```

ESP32会返回类似：

```text
MODBUS-RX:[01 04 48 ... CRC_L CRC_H]
```

目标地址1、2、3的本次请求应答都会输出到调试口；ESP32后台轮询应答不会输出。

站号1支持功能码`03`、`04`、`06`、`10`。保持寄存器`0x0000～0x000F`仅为调试RAM，上电清零且不触发机械动作；`0x0010`为显示帧率设置；`0x0011`为站3电机方向限制；`0x0100`为流程命令寄存器。输入寄存器如下：

| 地址 | 内容 |
|---:|---|
| `0x0000～0x0001` | ESP32固件版本，依次为主、次、修订、构建各1字节；`0.0.0.3`返回`00 00 00 03` |
| `0x0002` | 本机站号，固定为1 |
| `0x0003` | 网关协议版本，V1.29=`0x010A` |
| `0x0004～0x0005` | 站号2状态字、故障码 |
| `0x0006～0x0007` | 站号3实际RPM、MCSDK状态 |
| `0x0008` | 站号3状态位：bit0下加热、bit1上加热、bit2总开关 |
| `0x0009～0x000A` | 站号2离散输入位图 |
| `0x000B` | ESP32业务执行器状态位图 |
| `0x000C～0x0011` | 温度、电压、电流三个`float32`，ABCD字序；温度为ESP32按站号2 TMUX1308通道6 ADC标定换算后的值 |
| `0x0012` | 当前流程号：`0x51～0x56`，无流程为`0` |
| `0x0013` | 当前流程动作：开始=`1`、暂停=`2`、恢复=`4`，无流程为`0` |
| `0x0014～0x0015` | PSRAM当前可分配的8位堆余量，`uint32`，字节 |
| `0x0016～0x0017` | 内部RAM当前可分配的8位堆余量，`uint32`，字节 |
| `0x0018～0x0019` | 最近完整1秒窗口内实际完成的刷新帧数，`uint32`，数值也为FPS |
| `0x001A～0x001B` | 同一窗口平均刷新耗时，`uint32`，微秒，向下取整 |
| `0x001C～0x001D` | 同一窗口最大刷新耗时，`uint32`，微秒 |
| `0x001E～0x0020` | 蓝牙MAC地址，6字节，每寄存器高字节在前 |
| `0x0021` | 站3电机方向限制模式：0=不限制，1=只正转，2=只反转 |

单独读取开头的ESP32固件版本：`MODBUS-TX:[01 04 00 00 00 02 71 CB]`。当前固件应答为`MODBUS-RX:[01 04 04 00 00 00 03 BB 85]`。

周波值由ESP32每次站3后台轮询时通过FC03读取；站3的FC04输入寄存器快照本身不包含这两个保持寄存器。诊断字段均为高寄存器在前、寄存器内高字节在前，解析为`(high << 16) | low`；字节数除以1024得到KiB，微秒数除以1000得到毫秒。完整响应含72字节寄存器数据，RTU帧共77字节（含地址、功能码、字节数及CRC）。只读取诊断字段可发送：

```text
MODBUS-TX:[01 04 00 14 00 0A 30 09]
```

内存余量在查询时采集，表示空闲堆总量，不是最大连续块。显示统计从显示初始化开始划分固定1秒窗口，返回最近完整窗口，按最后一块DMA完成时刻归入窗口；一轮局部/全屏刷新只计一帧，多个DMA块不重复计数。耗时使用真实微秒时钟，从LVGL开始绘制脏区域到最后一块DMA传输完成，包含绘制、传输、等待及调度时间，不代表CPU或PSRAM利用率。启动未满1秒时显示统计为0；完整窗口没有刷新时三个显示字段均为0。查询不清零，建议每秒读取一次，静态画面FPS为0是正常的。

原有16/18/30/33寄存器读取仍兼容；上位机"ESP32全部状态"按钮应将读取数量改成34，并增加上述5个`uint32`显示项、蓝牙MAC字段和方向模式。站号2/3的完整状态缓存仍单独读取。

## 3. 不通过ESP32直接控制站号2

### 3.1 接线

站号2接口为 USART1：PA9/TX、PA10/RX，115200、8N1。

TTL串口连接：

```text
USB转串口 TX  → 站号2 PA10/RX
USB转串口 RX  ← 站号2 PA9/TX
USB转串口 GND ↔ 站号2 GND
```

必须确认USB转串口与MCU的电平兼容。若硬件接口经过RS-485收发器，则应连接A/B和GND，不能把USB-TTL直接接到A/B。

直连调试时应断开ESP32与站号2的TX/RX或确保ESP32不发送，避免两个主站同时驱动线路。

### 3.2 上位机设置

- 1000000、8N1、无流控。
- 选择HEX发送。
- 不发送 `MODBUS:`、方括号或空格字符。
- 不追加CR/LF。
- 发送内容必须包含CRC。

例如开启LED，上位机HEX发送框中填写：

```text
02 05 00 04 FF 00 CD C8
```

正常响应与请求相同：

```text
02 05 00 04 FF 00 CD C8
```

常用读取命令：

| 操作 | HEX发送帧 |
|---|---|
| 读取10个线圈 | `02 01 00 00 00 0A BC 3E` |
| 读取16个离散输入 | `02 02 00 00 00 10 79 F5` |
| 一次读取全部状态（80个输入寄存器，含V2追加区） | `02 04 00 00 00 50 09 04` |
| 读取前7个保持寄存器 | `02 03 00 00 00 07 04 3B` |

## 4. 不通过ESP32直接控制站号3

### 4.1 接线

站号3接口为 UART2：PA2/TX、PA3/RX，1000000、8N1。

TTL串口连接：

```text
USB转串口 TX  → 站号3 PA3/RX
USB转串口 RX  ← 站号3 PA2/TX
USB转串口 GND ↔ 站号3 GND
```

若使用RS-485接口，则连接对应A/B和GND。ESP32侧站3串口为TX=IO38、RX=IO39；直连时应断开ESP32的IO38/IO39连接或确保ESP32不发送，避免双主站冲突。

### 4.2 上位机设置

- 1000000、8N1、无流控。
- 选择HEX发送，不追加CR/LF。
- 不带 `MODBUS:` 和方括号。
- 帧末包含CRC低字节、CRC高字节。

站号3使用保持寄存器`0x0000`作为总开关，不使用线圈控制。设备上电后先发送：

```text
03 06 00 00 00 01 49 E8
```

然后发送具体动作，例如电机正转5档：

```text
03 06 00 04 00 05 09 EA
```

正常响应与请求相同。常用命令：

| 操作 | HEX发送帧 |
|---|---|
| 总开关打开 | `03 06 00 00 00 01 49 E8` |
| 总开关关闭 | `03 06 00 00 00 00 88 28` |
| 电机反转5档 | `03 06 00 04 FF FB C9 9A` |
| 电机停止 | `03 06 00 04 00 00 C9 E9` |
| 下加热5档 | `03 06 00 02 00 05 E9 EB` |
| 上加热5档 | `03 06 00 03 00 05 B8 2B` |
| 设置周波阈值18、总数100（FC10） | `03 10 00 31 00 02 04 00 12 00 64 9B 21` |
| 读取周波阈值和总数（FC03） | `03 03 00 31 00 02 94 26` |

通过ESP32 UART0/蓝牙网关发送时，在上述RTU帧外加 `MODBUS-TX:[...]`，例如：

```text
MODBUS-TX:[03 10 00 31 00 02 04 00 12 00 64 9B 21]
MODBUS-TX:[03 03 00 31 00 02 94 26]
```
| 读取10个线圈 | `03 01 00 00 00 0A BD EF` |
| 读取16个离散输入 | `03 02 00 00 00 10 78 24` |
| 读取前5个保持寄存器 | `03 03 00 00 00 05 84 2B` |
| 读取24个站3原生输入寄存器（含 PC2 ADC、电表数据及频率） | `03 04 00 00 00 18 F1 E2` |

## 5. 两种模式的关键区别

| 项目 | 通过ESP32 | 直接连接站号2/3 |
|---|---|---|
| 发送类型 | ASCII字符串 | 原始HEX字节 |
| 外层标记 | 请求必须有 `MODBUS-TX:[...]`，应答为 `MODBUS-RX:[...]` | 禁止添加 |
| CRC | 方括号内必须包含 | RTU帧末必须包含 |
| 波特率 | 固定115200连接ESP32 | 站号2为1000000；站号3为1000000 |
| 站号2/3正常应答 | 仅本次上位机请求的应答以 `MODBUS-RX` 输出 | 从站直接返回原始RTU帧 |
| 站号1 | 可访问ESP32本地寄存器 | 不适用 |

上位机周期刷新状态时，不要再把站号2/3的读取帧透传给下游。改为读取 ESP32（站号1）的缓存：

| 状态 | 请求帧 | 返回内容 |
|---|---|---|
| ESP32全部摘要状态 | `01 04 00 00 00 22 70 13` | 站号1输入寄存器`0x0000～0x0021`，共34个 |
| 站号2完整状态缓存 | `01 04 01 00 00 50 01 25` | 镜像站号2输入寄存器 `0x0000～0x004F`，共80个（含V2追加区） |
| 站号3完整状态缓存 | `01 04 02 00 00 1A 70 79` | 读取26个缓存寄存器：镜像站3逻辑快照 `0x0000～0x0019`，其中末尾2个是周波阈值/总数 |

站号3需运行支持输入寄存器 `0x0017` 及保持寄存器 `0x0031/0x0032` 的固件。若任一部分读取失败，ESP32保留上一份完整镜像并输出告警；请检查站号3固件版本和UART通信状态。

上述请求只读取 ESP32 RAM，不占用站号2/3串口。刚上电尚未取得对应站首份快照时会返回异常码 `04`，上位机稍后重试即可。

### 站号2抬升限位位图解析

最新站号2协议中，离散输入 `0x0000/0x0001` 恢复为抬升**合并高位/合并低位**；左右高位实际开关状态单独放在位图 bit14/bit15：

| 数据位 | 新含义 | 从站物理信号 | 上位机处理 |
|---|---|---|---|
| bit0（离散输入 `0x0000`） | 抬升合并高位 | 上行时左右均到位并锁存；静止时两侧开关同时触发 | 用作抬升高位到达判断 |
| bit1（离散输入 `0x0001`） | 抬升合并低位 | 编码器下行到位判断 | 用作抬升低位到达判断 |
| bit14（离散输入 `0x000E`） | 抬升左高实际状态 | PF6（原抬升高位开关） | 显示左侧实际开关状态 |
| bit15（离散输入 `0x000F`） | 抬升右高实际状态 | PA15（原抬升低位开关） | 显示右侧实际开关状态 |

读取 ESP32 站号1的镜像缓存 `0x0100～0x014F` 时，站号2输入寄存器 `0x000E` 位图对应镜像地址 `0x010E`；按 bit0/1 解析合并高/低位，按 bit14/15 解析左/右高位实际状态。直接读取站号2时，离散输入响应地址 `0x0000/0x0001` 同样表示合并高/低位。查询帧和报文格式不变，但应更新上位机标签及依赖此前“bit0/1=左/右高位”的流程判断。

若上位机读取站号1摘要位图 `0x0009～0x000A`，bit0/bit1 表示抬升合并高位/低位，bit14/bit15 表示抬升左/右高位实际状态。

ESP32后台按独立周期采集两个从站：站号2的完整状态计划采样周期为20 ms（每秒50次），站号3为100 ms（每秒10次）。上位机可根据所需数据的更新周期读取缓存；读取更快不会提高下游设备的实际采样率。上位机透传、业务写命令和通信超时可能使某次后台采样顺延。

## 6. 采集测试模式

用于通信质量诊断。发送 ASCII 命令（以换行 `\r` 或 `\n` 结尾）后，ESP32 停止后台自动轮询，以最快速度连续读取指定从站的全部输入寄存器并统计成功率。

| 命令 | 说明 |
|---|---|
| `TEST:02\r\n` | 开始站号2采集测试（读80个寄存器，默认超时） |
| `TEST:03\r\n` | 开始站号3采集测试（读24个原生输入寄存器，默认超时） |
| `TEST:02 VIOLENT\r\n` | 暴力模式：站号2测试，短超时（10ms/5ms），失败快速返回 |
| `TEST:03 VIOLENT\r\n` | 暴力模式：站号3测试，短超时（10ms/5ms） |
| `TEST:START 02 VIOLENT\r\n` | 同上，完整格式 |
| `TEST:END\r\n` | 停止测试，恢复正常自动采集 |
| `TEST:STATS\r\n` | 输出当前统计（测试中也可查询） |

应答格式：
- 启动：`TEST:START slave=02` 或 `TEST:START slave=02 violent`（暴力模式）
- 停止：`TEST:STOP`
- 统计：`TEST:STATS slave=02 attempts=N ok=N fail=N timeout=N crc=N invalid=N avg_us=N min_us=N max_us=N`

字段含义：
- `attempts`：总尝试次数
- `ok`：成功次数（`nmbs_read_input_registers` 返回 `NMBS_ERROR_NONE`）
- `timeout`：超时次数（从站无应答或应答不完整）
- `crc`：CRC校验失败次数
- `invalid`：其他错误次数（传输错误、非法响应等）
- `avg_us`/`min_us`/`max_us`：单次读取平均/最小/最大耗时（微秒）

说明：
- 测试期间不更新 `g_DataPool` 和镜像缓存，上位机读取站号1镜像区将返回测试前的最后快照。
- **默认模式**：沿用业务通信超时（响应100 ms、字节20 ms），从站离线时每次失败约100 ms。适合评估真实业务通信质量。
- **暴力模式**（`VIOLENT`关键字）：短超时（响应10 ms、字节5 ms），从站离线时每次失败约10 ms，吞吐量约10倍。适合压测从站最大响应能力，但可能把慢速从站误判为超时。退出测试后自动恢复业务超时。
- 实际周期受物理限制：1 M波特率下站号2读80个寄存器（请求8字节+响应165字节）传输时间约1.9 ms，加上DE切换和总线等待，实际平均周期约2~3 ms；站号3读24个寄存器传输时间约0.61 ms，实际周期约1 ms。
- 测试期间每5秒自动打印一次统计，无需手动发送 `TEST:STATS`；手动查询仍然可用。
- 测试期间仍可接收 `MODBUS-TX:[...]` 透传帧和 `TEST:STATS`/`TEST:END` 命令，但业务写命令会被命令队列阻塞直到测试结束。

## 7. 安全与故障排查

- 电机、泵、阀门和加热命令会实际驱动硬件，测试前确认机械结构、液路、功率回路和急停条件安全。
- 无应答时依次检查波特率、站号、HEX/ASCII模式、TX/RX交叉、共地和CRC顺序。
- 直接连接时不得让ESP32和PC同时作为主站发送。
- 功能码05、06正常响应与请求相同；异常响应的功能码为原功能码加 `0x80`。
- 错误站号和错误CRC通常无应答。
- 站号3总开关关闭时，非零档位不会启动设备；关闭总开关会清零三路档位。
- `HEARTBEAT`只证明ESP32调试任务仍在运行；判断站号2/3是否在线，应主动发送只读命令并检查对应的`MODBUS-RX`。
